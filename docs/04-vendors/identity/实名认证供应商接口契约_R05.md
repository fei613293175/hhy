## 调用与安全边界

- 三个接口均为 `POST application/x-www-form-urlencoded`，使用 `Authorization: APPCODE <secret>`。
- APPCODE 只从激活供应商版本的 SecretRef 解析，仅在单次请求内存中存在，请求结束立即清零。
- 端点必须为无凭据、无片段、无本地地址的 HTTPS；禁止自动跟随重定向。
- 单次 JSON 响应上限 64 KiB；人脸图片提交使用 Base64 `image`，上限 100 KiB，不使用供应商公开 `url` 做人脸比对。
- 供应商 `msg`、`desc`、照片地址、订单号、原始响应和结果码均不得进入商业前端。

## 活体照片下载

- 下载器不跟随重定向，域名解析结果中的每一个地址都必须是公网单播地址；本机、内网、链路本地和组播地址全部拒绝。
- 只接收 `image/jpeg` 或 `image/png`，并校验正文魔数与声明类型一致。
- 下载正文最多 100 KiB，只在内存中短时存在，同时计算 SHA-256；不写临时文件、不记录来源 URL 或图片内容。
- 下载失败只返回统一可重试业务错误，不能携带第三方正文、地址或网络异常细节。

## 活体结果查询

- 端点：`identity.liveness.result_url`，冻结路径 `/api/liveness/h5/result`。
- 请求：`orderNo` 必填；本版不发送定制字段 `hbId`。
- 成功信封：`success=true`、`code=200`、`data` 为对象，响应 `orderNo` 必须与请求一致。
- `data.result=0`：活体通过，必须同时返回安全 HTTPS `faceImageUrl`。
- `data.result=1`：活体拒绝，不读取或展示供应商原因原文。
- `data.result=2`：结果尚未生成，保持处理中，不得伪造成功或失败。
- 其他结果、订单不一致、畸形/超限响应和非 2xx HTTP 均归为可重试供应商不可用，不改变实名终态。

## 身份证人脸比对

- 端点：`identity.face_compare.url`，冻结路径 `/face_id_card/check`。
- 请求：`idcard`、`name`、`image` 必填；`url` 不发送。
- 成功信封：`success=true`、`code=200`、`data` 为对象。
- `resultCode=1001`：自动通过；激活配置 `identity.face_compare.auto_pass_code` 必须与其一致。
- `resultCode=1002`：进入人工复核；激活配置 `identity.face_compare.manual_review_code` 必须与其一致。
- `resultCode=1003`：不同人，拒绝。
- `resultCode=1004`：无法识别或身份信息不一致，拒绝。
- `score` 如存在必须在 0 到 1 之间；`birthday/address/sex/msg` 仅属于加密供应商证据，不作为前端直出字段。

## 后续状态机约束

本契约已冻结真实供应商端口、解析和安全下载。只有在校验后的活体照片已保存到 `private_kyc`，供应商原始响应已加密持久化，且人脸比对结果与会话乐观锁在同一事务落库后，才允许把会话推进为 `VERIFIED`、`MANUAL_REVIEW` 或 `REJECTED`。

CR-0099 已实现上述编排与 PostgreSQL 事务边界：供应商待处理响应首次加密落库后进入 `PROVIDER_PROCESSING`；活体通过响应在图片下载前加密保存；图片存储返回的内部媒体ID、人脸比对密文、`identity_media`、会话、身份档案和 Outbox 以会话 `expectedVersion` 收口。真实 `private_kyc` 写入适配器未激活时统一返回可重试商业错误，不写终态，也不使用公开URL或本地临时文件降级。
