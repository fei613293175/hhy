# 多对象存储适配规范 V1.2

- `ObjectStorageProvider` 统一提供 put/get/head/delete/presign/copy/listMultipart 能力。
- 默认 Cloudflare R2，同时支持阿里云 OSS，业务代码不得依赖具体 SDK。
- 每个对象必须记录 provider、bucket、objectKey、scope、owner、bizType、bizId、MIME、size、SHA256、visibility、status。
- 实名、聊天、证据、备份一律私有；后台预览必须鉴权、短时地址、动态水印和审计。
- 跨供应商迁移采用复制、校验 SHA256、切换引用、观察期、延迟删除的流程，可断点续传和回滚。
- 第三方App禁止上传APK；`apk_release`只保存合伙云 Pro 官方构建产物。

## Cloudflare R2 运行时门禁（CR-0104）

- R2 通过 AWS SDK for Java 2.x 的 S3 兼容接口接入，Region 固定为 `auto`；业务服务只依赖 `StorageObjectPort`，不得直接依赖 SDK。
- 每次对象操作必须使用 `storage_scope_bindings.config_version_id` 指定的精确配置版本；该版本必须属于 `storage`、状态为 `ACTIVE` 且最近真实连接测试成功。不得改读“最新配置”或注册表默认值。
- 绑定中的 provider、endpoint、bucket 必须与该配置版本完全一致。任何漂移、缺项、非 HTTPS 地址或私网/本机地址都必须失败关闭。
- Access Key ID 与 Secret Access Key 只允许以 `SecretRef` 保存和解析。运行时短时取得的字符数组必须在 SDK 调用结束后清零，不得进入日志、异常、数据库、URL或响应。
- 上传使用短时 presigned PUT，签名必须绑定 `Content-Type` 和 `x-amz-meta-sha256`；对象键由 `scope/owner/SHA256(idempotencyKey)` 稳定派生，重复请求不得产生新对象。
- 完成上传必须执行 HEAD，并同时核对 objectKey、Content-Length、`x-amz-meta-sha256` 和 ETag；任一不一致均不得登记媒体或推进业务状态。
- 私有 Scope 只允许短时 presigned GET，不得产生 public URL；签名有效期取激活配置 `storage.signed_url.ttl_seconds`，运行时仅接受 30–1800 秒，私有预览仍受上层五分钟上限约束。
- 当前 Cloudflare R2 端口已实现；不得回退到本地文件或伪造成功。

## 阿里云 OSS 运行时门禁（CR-0106）

- OSS 使用官方 Java SDK 3.18.5 和 V4 签名；Region 必须取自精确激活配置，不得从 Endpoint 猜测或在代码中硬编码。
- 每次对象操作同时核对 `storage.scope.<scope>.provider=ALIYUN_OSS`、绑定的 endpoint/bucket 与 `config_version_id` 指向的 `ACTIVE`、连接测试成功配置。`storage.default_provider` 不得覆盖作用域选择。
- AccessKey ID 与 AccessKey Secret 只允许通过 `SecretRef` 即时解析，SDK 使用结束后必须关闭客户端并清零字符数组；不得缓存、回显或写入日志。
- 上传使用 V4 presigned PUT，并绑定 `Content-Type` 与 `x-oss-meta-sha256`；对象键与 R2 使用相同的稳定派生规则，保证切换供应商后幂等语义不变。
- 上传完成必须通过 HEAD 同时校验 Content-Length、`x-oss-meta-sha256` 与 ETag；任一不一致均失败关闭。私有读取只返回受激活 TTL 和上层五分钟门禁约束的 V4 presigned GET。
- 删除、分页扫描和同一精确配置内的服务端复制由 OSS 真实端口执行；跨配置或跨供应商复制不得伪装为服务端复制，必须交由迁移编排的下载、校验、上传流程。
- R2 与 OSS 均已接入生产端口；正式环境仍必须分别提供真实 SecretRef、激活配置和最小端到端回执后，才能关闭供应商交付门禁。
