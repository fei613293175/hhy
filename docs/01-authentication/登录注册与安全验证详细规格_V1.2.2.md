# 登录、注册、短信与安全验证详细规格 V1.2.2

> R02 安全验证码的用户可见交互、尺寸、文案、状态和错误恢复统一引用：
> [`../02-ui/R02安全验证码弹层交互与视觉规格_V1.2.2.md`](../02-ui/R02安全验证码弹层交互与视觉规格_V1.2.2.md)。
> 本文件定义业务流程和安全边界；专用 UI 规格覆盖原自动生成页面表中关于挑战字段“可见展示”的通用描述。

## 1. 强制原则

- App 启动后必须登录，未登录不得进入首页。
- 默认登录方式是 **手机号 + 登录密码**。
- 同时支持 **手机号 + 短信验证码登录**。
- 密码登录提交前必须通过安全验证；短信验证码发送前也必须通过安全验证。
- 首版安全验证采用后端生成的图形验证码，预留滑块、行为验证或第三方人机验证适配器。
- **安全验证码在认证页面初始状态完全隐藏**，不得以页面内联区或“创建安全验证”按钮出现。
- 用户点击真实业务按钮后，客户端自动创建挑战并打开居中模态对话框；验证成功后自动继续原业务意图。
- 短信由 **阿里云短信** 发送，业务代码通过 `SmsProvider` 抽象，不在客户端保存 AccessKey。
- 注册是独立流程，不再采用“短信登录即自动注册”。
- 邀请关系只在首次注册时建立，绑定后用户不能自行修改。
- 安全验证码答案、密码和短信码只在内存中短暂存在，不进入日志、埋点、URL 或明文缓存。

## 2. App 登录首页

默认显示密码登录表单：

1. 手机号；
2. 登录密码；
3. 登录按钮；
4. 密码登录 / 短信验证码登录切换；
5. 忘记密码入口；
6. 注册账号入口；
7. 用户协议和隐私政策状态。

初始页面 **不显示**：

- 图形验证码图片；
- 安全验证码答案输入框；
- “创建安全验证”按钮；
- `challengeId`、Token、Nonce、设备指纹、Base64 或请求编号。

用户完成本地字段校验后点击“登录”或“发送验证码”，客户端才自动打开安全验证码 Dialog。效果图 B01 中出现的“短信登录默认页”和第三方微信/QQ/支付宝登录图标只作为布局参考。首版不实现第三方登录，默认入口必须是密码登录。

## 3. 安全验证码通用编排

### 3.1 创建挑战

既有接口：

`POST /api/v1/auth/security-challenges`

提交内部字段：

- `scene`；
- `clientNonce`；
- 可选 `deviceFingerprint`；
- `X-Idempotency-Key`。

返回内部字段：

- `challengeId`；
- `challengeType`；
- `expiresAt`；
- `imageBase64` 或未来 Provider 所需内部 `token`。

这些字段只进入客户端内存状态。用户只看到验证码图片、有效期、人类可读提示、答案输入和操作按钮。

### 3.2 没有独立验证接口

现有契约没有单独的“验证图形验证码”接口。“验证并继续”会把用户答案映射为原业务请求中的 `challengeProof`，与原业务一起提交：

- 密码登录：`POST /api/v1/auth/password/login`；
- 登录/注册/重置密码短信：`POST /api/v1/auth/sms/send`。

因此，安全验证成功和原业务请求成功由同一次业务响应确认。不得在客户端伪造“本地验证成功”，也不得为了 UI 额外增加 API。

### 3.3 一次性和防重

- 同一页面同时最多一个待处理业务意图、一个挑战创建请求和一个原业务提交请求。
- 连续点击不得并行创建挑战或重复发送短信/登录。
- 主动刷新验证码使用新的 `clientNonce` 和新的挑战创建幂等键。
- 原业务请求结果未知且请求体不变时，重试复用原业务幂等键。
- 取消、离开页面、切换登录方式或挑战到期后，不得继续复用旧答案。

## 4. 密码登录

### 4.1 触发

1. 用户输入手机号、密码并满足页面既有协议规则。
2. 点击“登录”。
3. 客户端完成本地字段校验；不通过时只显示原页面字段错误，不打开安全 Dialog。
4. 校验通过后打开 Dialog 并创建 `scene=LOGIN` 的挑战。
5. 用户输入答案并点击“验证并继续”。
6. 客户端提交密码登录请求。

### 4.2 登录请求

`POST /api/v1/auth/password/login`

提交：

- 手机号；
- 密码；
- `challengeId`；
- `challengeProof`；
- 设备信息；
- App 版本；
- `X-Idempotency-Key`。

### 4.3 成功和错误

- 成功：Dialog 显示 `验证通过，正在登录…`，短暂停留后关闭并进入登录成功导航。
- 挑战答案错误或到期：留在 Dialog，清空答案并换新图，不清空手机号、密码和协议状态。
- 账号或密码错误：清除一次性挑战并关闭 Dialog，由登录页显示统一的账号/凭证错误，不得误报为图形验证码错误。
- 用户取消：保留表单，不提交登录。

### 4.4 安全规则

- 密码使用 Argon2id；无法使用时使用 BCrypt，禁止明文和可逆加密。
- 登录错误不得区分“手机号不存在”与“密码错误”，统一提示账号或凭证不正确。
- 默认同一手机号连续失败 5 次锁定 15 分钟，后台可配置。
- 同一 IP、设备、手机号分别限流。
- 风险设备可以提高验证强度、延长锁定或进入人工风控。
- 安全挑战一次性使用，默认 120 秒有效；验证失败后按规则刷新。
- 登录成功轮换会话 Token，记录设备、IP、App 版本和风险结果。

## 5. 短信验证码登录

流程：

1. 输入手机号。
2. 点击“发送验证码”。
3. 本地手机号校验通过后，自动打开安全 Dialog，创建 `scene=LOGIN` 挑战。
4. 点击“验证并继续”后请求发送登录短信。
5. 短信发送成功后关闭 Dialog，开始倒计时并聚焦短信验证码输入框。
6. 输入短信验证码并登录。
7. 手机号未注册时不得自动创建账号，提示先注册。

接口：

- `POST /api/v1/auth/security-challenges`；
- `POST /api/v1/auth/sms/send`，`scene=LOGIN`；
- `POST /api/v1/auth/sms/login`。

规则：

- 图形安全验证码只用于本次短信发送，最终短信登录不再次弹出图形验证码。
- 安全 Dialog 取消时不发送短信，手机号继续保留。
- 短信发送成功后，图形挑战立即清除，不能用于第二次发送。

默认种子值：

- 6 位数字验证码；
- 5 分钟有效；
- 60 秒发送冷却；
- 单验证码最多校验 5 次；
- 同手机号每日发送上限 10 次；
- IP、设备和全局通道上限后台配置。

## 6. App 注册

### 6.1 表单输入项

- 手机号；
- 登录密码；
- 确认密码；
- 邀请码；

邀请码固定必填。注册不发送短信验证码，也不要求用户手动加载或提交协议版本。

### 6.2 注册验证步骤

1. 校验手机号格式。
2. 校验密码和确认密码一致。
3. 校验邀请码非空；服务端在最终注册请求中复核有效性。
4. 用户点击“注册”。
5. 客户端打开安全 Dialog，创建 `scene=REGISTER` 挑战。
6. 用户点击“验证并继续”，客户端把 `challengeId` 与 `challengeProof` 随注册请求一次提交。
7. 服务端验证一次性图形挑战、密码规则和邀请码。
8. 创建用户、凭证、资料和邀请关系。
9. 生成随机用户名。
10. App 注册成功后自动创建登录会话并进入首页。

接口：

- `POST /api/v1/auth/security-challenges`；
- `POST /api/v1/auth/invite-codes/validate`；
- `POST /api/v1/auth/register`。

注册请求字段为 `phone`、`password`、`inviteCode`、`challengeId`、`challengeProof` 和客户端自动生成的 `device`；不得提交 `smsCode` 或 `agreementVersions`。

### 6.3 密码规则

默认：

- 8–20 位；
- 至少包含字母和数字；
- 禁止常见弱密码；
- 禁止与手机号完全相同；
- 后台可调整复杂度，但不能降低到明文或无密码。
- 注册、忘记密码和修改密码页面必须在密码输入框下持续展示“8–20位，需同时包含字母和数字”；输入后不满足规则时使用字段级错误色，确认密码不一致时明确提示，不得只通过禁用按钮暗示规则。
- 密码登录页允许提交既有兼容长度的密码，客户端不得因新密码策略变化阻断老账号登录；新建或重置密码严格执行当前冻结策略。

### 6.4 随机用户名

注册成功后生成：

`合伙人 + 随机数字`

示例：`合伙人6483`。

规则：

- 默认生成 4 位数字；
- 必须保证昵称唯一或附加唯一用户号；
- 冲突时重试；达到重试阈值后扩展为 5–6 位数字；
- 用户后续可按平台规则修改昵称。

## 7. H5 邀请注册

路由：`/invite/{code}/register`

规则：

- 邀请码必须存在且有效。
- URL 中的邀请码默认锁定展示，用户不能改成其他邀请码；若 URL 未携带邀请码，则必须手动填写有效邀请码后继续。
- 表单包括手机号、密码和确认密码；不发送注册短信验证码，经过安全验证后直接注册。
- 安全验证初始隐藏，点击“注册并下载 App”后以 H5 模态组件自动出现；交互语义和 Android 专用规格一致。
- 注册成功后绑定邀请关系。
- 注册成功后自动跳转品牌 App 下载页，例如：`/?registered=1&invite_code=XXXX`。
- 下载页继续显示品牌介绍、Android 下载按钮、二维码和安装指引。
- H5 注册不创建可在网页长期使用的业务会话；只返回一次性成功状态，避免共享设备泄露。

## 8. 忘记密码与修改密码

### 8.1 忘记密码

页面包含：

- 手机号；
- 新密码及页面现有本地确认规则；
- 短信验证码；
- 发送验证码；
- 重置密码。

流程：

1. 用户点击“发送验证码”。
2. 本地校验通过后打开安全 Dialog，创建 `scene=RESET_PASSWORD` 挑战。
3. 点击“验证并继续”后发送重置密码短信。
4. 发送成功后关闭 Dialog，开始倒计时并聚焦短信验证码输入框。
5. 用户输入短信码并提交重置。
6. 成功后使其他 Refresh Token 失效，可配置是否保留当前设备会话。

接口：

- `POST /api/v1/auth/security-challenges`；
- `POST /api/v1/auth/sms/send`，`scene=RESET_PASSWORD`；
- `POST /api/v1/auth/password/reset`。

最终点击“重置密码”不重复弹出图形验证码。

### 8.2 已登录修改密码

- 原密码；
- 新密码；
- 确认新密码；
- 安全验证可按风险触发。

接口：`POST /api/v1/me/security/password/change`。

如后续将安全验证码用于已登录敏感操作，仍复用本规格的 Dialog 结构，但 `scene=SENSITIVE_OPERATION`，并通过单独 CR 补齐页面触发点。

## 9. 安全 Dialog 生命周期

```text
HIDDEN
→ REQUESTING_CHALLENGE
→ READY / INPUTTING
→ SUBMITTING_INTENT
→ SUCCESS_CONTINUING
```

异常分支：

```text
WRONG_ANSWER
EXPIRED_REFRESHING
NETWORK_ERROR
RATE_LIMITED
CANCELLED
```

详细进入条件、文案、尺寸、动画、键盘和恢复行为以专用规格为准。

## 10. 后台配置项

- 默认登录方式：固定 `PASSWORD`；
- 是否开放短信登录；
- App 注册邀请码是否必填；
- H5 邀请注册邀请码：固定必填；
- 图形验证码开关和难度；
- 安全挑战有效期和失败次数；
- 密码长度、复杂度、弱密码库；
- 登录失败锁定次数与时长；
- 短信验证码长度、有效期、冷却、日限额；
- 阿里云短信模板、签名和场景映射；
- 随机用户名前缀和数字位数；
- 邀请关系绑定策略和风险规则。

配置变更只影响新请求，登录日志、短信发送记录和注册记录必须保留当时规则版本。
