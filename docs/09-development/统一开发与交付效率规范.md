# 合伙云 Pro 统一开发与交付效率规范

状态：`APPROVED · CR-0081 + CR-0082 + CR-0150 + CR-0152 + CR-0247 + CR-0248`

## 同一任务内的多 Story 推进

- 一个 Task 明确包含多个可独立施工 Story 时，完成当前 Story 的实现提交后使用 `continuity.py story-switch` 原子切换，禁止调用 `close` 把尚未完成的整个 Task 标记为 `DONE`。
- 切换只允许当前 Actor 在干净工作树、最新检查点已提交、目标 Story 为 `READY_FOR_IMPLEMENTATION` 时执行；Task 和唯一 ACTIVE Claim 保持不变。
- 新 Story 不得复用旧 Story 检查点。切换后必须重新读取事实源、创建 CR（需要时）、完成对应验证并生成新检查点。

## 1. 核心原则

质量门禁必须与风险相称。简单任务不得因为流程习惯被升级成完整版本发布；高风险任务也不得为了速度跳过安全、契约、数据库或发布门禁。对话不是事实源，任何电脑和任何 AI 均以本文件、`config/development-workflow.yaml`、当前 Context Pack 和统一脚本输出为准。

统一入口：

```powershell
python scripts/hhy_workflow.py resume
python scripts/hhy_workflow.py plan --intent bugfix
python scripts/hhy_workflow.py run --intent bugfix
python scripts/hhy_workflow.py hotfix --changed-file <PATH>
```

## 2. 五种模式

- `SIMPLE`：单模块、低风险、小范围维护或Bug。普通维护只运行受影响FAST检查；Bug至少运行受影响MODULE回归。不得执行全量集成、APK或版本关闭，除非实际影响触发升级。
- `STANDARD`：单一产品域正式功能或数据库、契约、安全等高风险小范围变更，运行受影响MODULE门禁。
- `CROSS_LAYER`：两个及以上产品域，分别运行模块门禁；完成纵向切片时由主控执行一次INTEGRATION。
- `TEST_APK`：明确需要真机回归时使用。先验证精确下载路由，再从冻结Commit构建一次，完成固定签名、正式测试API和四方SHA；不得标记为版本关闭。
- `RELEASE_CLOSE`：仅用于大版本机器收尾。RELEASE全量门禁必须已经在该版最终候选阶段由`obx-test`/GitHub固定工具链执行一次并形成同一源码Commit的不可变证据；机器收尾只核验候选、截至当前版本的累计视觉债务、APK身份与四方SHA、Staging、文档、桌面APK、测试说明及六项全局漂移审计，不在本机安装Java/Android SDK，也不重复Maven、PostgreSQL、Android或模拟器。项目所有者真机结果允许异步`PENDING`；全部机器证据通过后才可无状态交接到下一版本。

`auto`不会擅自把产品代码认定为简单Bug；开发者明确输入`--intent bugfix`后，只有满足低风险、小范围、单产品域条件才进入`SIMPLE`。

版本关闭只分为两个明确阶段，不再使用含义不清的“关闭”命令：

- 机器收尾：统一入口为 `python scripts/hhy_workflow.py run --intent release-close --release <RELEASE>`，内部只允许调用 `--machine-close-gate`。它证明该版已形成可测试、可追溯、可继续开发的完整候选，不等待项目所有者逐版本反馈。
- 生产验收：仅在项目所有者明确真机 `PASS` 后执行 `python scripts/check_release_artifacts.py --release <RELEASE> --production-close-gate`。该阶段继续硬校验真机结果、Release Commit、Tag、生产终态和激活条件，但只核验已有不可变证据，不重新编译、打包或启动模拟器。

旧参数 `--close-gate` 必须拒绝执行并提示二选一，任何 AI 或开发者不得猜测用户所指阶段。机器收尾已通过后，真机仍为 `PENDING` 时禁止反复调用生产验收门禁制造伪失败；反馈到达后只运行生产验收，不重跑已经通过且输入未变化的构建、单测、Lint、集成或模拟器作业。

## 3. 禁止“大炮打蚊子”

以下情况默认不得创建多个CR、运行全项目集成或重新交付APK：

- 单个页面的非冻结文案、样式或局部状态Bug；
- 单个模块内有明确复现和回归测试的代码缺陷；
- 文档、测试或开发工具的机械修正；
- 不改变数据库、公开契约、安全策略、资金状态、生产配置或版本身份的变更。

只有命中冻结事实、数据库迁移、公开契约、安全、资金、生产基础设施、APK身份或版本关闭时才升级。机器输出必须列出升级路径和原因，禁止只写“为了保险”。

## 4. APK先预检再构建

冻结源码Commit后、开始Android构建前执行：

```powershell
python scripts/deliver_android_test_apk.py preflight-route `
  --release R03 `
  --commit <40位Commit> `
  --ssh-alias obx-test `
  --remote-root /www/wwwroot/download.orbexa.cc
```

该命令只验证SSH、远端根目录和Nginx精确文件路由，不上传APK、不修改交付状态。正式`prepare`会再次执行同一预检，并在任何复制、上传动作前失败。禁止在路由未通过时启动正式APK构建或请求尚不存在的公网URL，以免形成CDN缓存404。

## 5. 断点与耗时

- 测试计划按文件影响选择，已通过且输入未变化的阶段不得无故重跑。
- `hhy_workflow.py run`把每个检查的输入指纹、结果和耗时原子写入忽略目录`.continuity/runtime/hhy-workflow-state.json`；相同输入再次执行会跳过既有PASS项，从第一个未通过节点继续。只有明确传入`--fresh`才允许重跑。
- 网络失败优先重试上传或验证阶段，不得为修复下载路由重新修改业务源码或重建APK。
- 候选在业务测试开始前因 GitHub、网络、镜像或 Staging HTTP 5xx 等有日志证据的瞬态故障失败时，只允许同一 Commit 重跑失败作业及其依赖一次；禁止重跑已通过阶段。若同一瞬态再次出现，停止重跑并诊断 Staging/基础设施，不得继续消耗候选轮次碰运气。
- 项目所有者真机反馈按异步队列处理，不要求逐版本即时反馈；`owner_physical_test=PENDING` 不得成为后续依赖已满足开发、机器候选和桌面 APK 累积交付的等待点，但继续阻断该版正式验收和生产激活。
- 每个检查记录独立耗时；单项超过10分钟必须记录具体瓶颈。
- `SIMPLE`目标30分钟、`STANDARD`目标60分钟、`CROSS_LAYER`目标90分钟、`TEST_APK`目标75分钟；目标超时是排查信号，不是跳过测试的理由。
- 大版本全量集成只在最终候选阶段执行一次；`RELEASE_CLOSE`使用专用`MACHINE_CLOSE`检查档，不包含本机Maven、PostgreSQL、Android或模拟器。候选已经绑定相同源码Commit且报告PASS时，关闭阶段只校验证据、SHA和页面清单；只有候选源码或其真实依赖变化才回到最终候选阶段重新生成候选。`artifacts/validation/**`等由门禁写回的生成证据不参与工作分类或缓存输入指纹，禁止因报告时间戳变化重跑已通过节点。
- R12 起最终候选之后必须补一份绑定候选源码 Commit 的六项治理审计报告，覆盖开发文档、硬门禁执行、进度、复用模式、问题登记和踩坑记录，并在 Release Manifest 记录报告路径与 SHA-256。审计只复用已有 Doctor、计划和视觉校验结果，不重复 Android/Java/PostgreSQL 重型门禁；发现漂移则先原位修复并重新运行受影响轻量门禁。
- 修改 `config/test-impact-map.yaml` 必须运行受影响选择器和统一工作流测试，但映射文件本身不属于 Android 源码或构建输入，不得仅因该文件变化启动 Android 编译、单测或 Lint；Android 自动化策略、工作流、门禁脚本、测试或应用源码变化仍照常触发 Android MODULE。
- `.continuity/**`、Context Pack 与由同一连续性命令同步生成的会话、CR、任务迁移索引只由连续性门禁验证，不得因生成索引位于 `catalogs/` 就误触发 OpenAPI/运行时资产校验；真实业务目录文件变化仍按原映射执行。

## 6. 跨电脑和跨AI

统一入口自动解析当前Python以及`HHY_GIT_BIN`、`HHY_PNPM_BIN`、系统PATH和Codex捆绑运行时。新环境不得因为PATH缺少Git就重建仓库，也不得因为本机缺少Android SDK而重建云端镜像。

Windows 首次接手必须运行 `powershell -NoProfile -ExecutionPolicy Bypass -File scripts/configure_windows_git_runtime.ps1`，再以 `-Check` 回读。脚本只在用户级持久化 `HHY_GIT_BIN` 和 Git `cmd` 目录，幂等去重，不修改系统级 PATH、凭据或远端。若旧的用户级覆盖路径已失效，安装模式会从系统 Git 或 Codex 受控运行时修复，检查模式必须明确失败。长驻 Codex/IDE 可能保留启动时环境；当前任务使用显式 `HHY_GIT_BIN` 或 `hhy_workflow.py git` 继续，在方便时重启一次刷新，禁止每条命令重新摸排或临时猜路径。

项目所有者已对本项目开发所需的终端、PowerShell、SSH 和仓库内工具执行给出长期授权；该授权允许 AI 自主执行，但明确禁止把终端确认框、Git Credential Manager 对话框或权限选择转交项目所有者。执行前必须优先复用当前环境已允许的命令前缀、`hhy_workflow.py git`、受控 Git/Python/Node 路径和工作区写入通道；若某种写法会触发新的交互授权，必须改用等价的静默通道，不得反复换写法试探弹窗。读取 GitHub Actions 或下载已登录构件时优先使用现有浏览器登录态或无凭据 HTTPS，不得为只读操作调用 Git Credential Manager。只有仓库定义的真实外部秘密、账号权限或商业决策缺失才可阻断受影响项，客户端授权弹窗本身不得成为开发等待点。

换电脑恢复顺序固定为：运行上述配置脚本并 `-Check` → `restore_git_transport.py status` → `continuity.py resume` → `restore_git_transport.py push-preflight`（工作区应干净时）。任何脚本调用 Git 必须依次解析显式 `HHY_GIT_BIN`、系统 PATH、受控运行时；裸 `git` 只允许在配置检查已 PASS 后使用。

任何接手者先运行`resume`，再按输出选择意图。执行代理只能处理路径互斥模块，主控独占连续性记录、契约集成、数据库、安全和发布；并行不得产生第二个事实会话。

## 7. 热修复快速通道

- `hotfix`固定使用`bugfix`意图，时间盒为定位10分钟、实现15分钟、交付10分钟，总目标35分钟；超时只触发瓶颈记录，不允许跳过必要测试。
- 断点状态按每个检查自身命令与实际输入文件计算指纹。只修改Android文件时，已通过且输入未变化的后端检查可直接复用，反之亦然。
- `--parallel-workers 2`仅允许`CROSS_LAYER`或`TEST_APK`，且必须同时提供40位`--frozen-commit`；脚本会硬校验工作区干净且HEAD完全一致。未冻结、脏工作区和简单任务均拒绝并行。
- Git Hooks不再依赖当前PowerShell的PATH。统一使用`python scripts/hhy_workflow.py git status|stage|commit|push`，它会自动注入当前Python、受控Git与pnpm路径。
- 测试APK换版使用`prepare --replace-existing`。新APK只有完成路由、服务器和HTTPS验证后才会替换当前清单；旧清单和交付证据自动归档到其7位Commit目录。任何失败都会保留原交付状态。
- `--replace-existing`只能替换尚未获得项目所有者真机PASS的测试包，且新`versionCode`必须严格递增；已经验收的交付不能被重置。

## 8. 大型商业 App 成熟方案优先

- 基础架构优先选择官方 Stable、行业主流、具备长期维护与迁移路径的方案；不得自行实现已有成熟库能够解决的导航、返回栈、图标系统、状态保存、动效、网络或安全基础能力。
- 禁止把 Alpha、Beta、RC、停止维护库或无生产案例的小众方案引入主开发线；版本目录和依赖门禁必须阻止预发布基础组件。
- Android 统一使用稳定 Jetpack Navigation Compose、Material 矢量图标的项目语义封装、`rememberSaveable`/SavedState 和 Design Token 动效；各页面只组合公共能力，不重复实现。
- “成熟方案优先”不允许覆盖冻结效果图、业务合同和安全边界。框架负责技术能力，页面视觉和业务仍以冻结事实源为准。
- 必须自定义时只扩展最小业务差异；先提交 ADR 与 CR，记录为什么主流方案不足、如何兼容和回退，并补充自动回归。

## 9. Android 自动开发和修复

- R06 起所有 Android 版本候选统一调用 `.github/workflows/android-quality-gate.yml`，不得另写一次性打包命令绕过模拟器、截图或日志检查。
- 普通 Android 提交通过 `candidate=false` 只运行源码/策略、正式 API、编译、单测、Lint 与打包，禁止启动模拟器或上传候选；目标是稳定提供 2 至 4 分钟级反馈，而不是把每个提交当作版本封板。
- 候选检查点把 `config/android-candidate-request.yaml` 更新为新的唯一 `request_id` 并提交；`.github/workflows/android-candidate-request.yml` 校验 Release、候选标记和 1 至 3 的修复轮次后，调用同一权威质量门禁。默认分支已注册手动入口时仍可使用 `workflow_dispatch(candidate=true)`，两条入口不得分叉实现。
- 失败运行必须生成机器可读报告和耐久修复项；接续 AI 下载证据后执行“分析—最小修复—重打包—重测试”，直至 PASS。
- 同一根因最多三轮 AI 修复；业务失败不得仅重跑，第三轮后只有真实外部权限/秘密/商业决策阻断才可请求项目所有者。
- `candidate-report.json.status=PASS` 且 `owner_test_allowed=true` 之前不得把 APK 复制到桌面。PASS 后由 AI 直接交付并继续下一版本；项目所有者按自己的时间逐一测试，反馈进入后续修复队列，不得成为等待点。生产激活继续要求独立的项目所有者验收。
- 每个 Release 必须使用 `tests/android/visual-manifests/<Release>.yaml` 选择实际受影响页面；禁止把固定认证截图机械应用到无认证变化的版本。AI 按页面身份、真实加载、像素稳定、跨页差异、截图哈希和冻结视觉规格自主接受基线。
- 仅在“跨历史版本集中 UI 返工”这类明确批准的全局视觉审计中，允许把既有 `config/android-candidate-request.yaml` 设置为唯一组合 `release=HISTORICAL-UI`、`candidate=false` 并提交一次；已注册的 `.github/workflows/android-candidate-request.yml` 必须把该布尔值原样传给现有 `.github/workflows/android-quality-gate.yml`。该模式只渲染生产 Composable，测试夹具必须位于 `androidTest`、离线且不得进入发布包；它不请求服务器账号、不生成候选 APK、不执行发布门禁，也不能替代任何大版本最终候选。截图由 AI 逐张对照批准效果图或可复用视觉规格后登记，失败页面回到源码修复，不得把测试夹具内容当成产品业务事实。禁止另建平行视觉工作流或借用完整候选模式。
- 本机缺少 Android 模拟器硬件加速时，不得在开发中途反复尝试 AVD、擅自启用 Windows 功能或要求项目所有者立即重启；先完成可在本机确定的编译、单测和静态门禁，再使用上述一次性手动视觉专跑取证。换电脑后若本机加速可用，仍执行同一测试类与同一截图清单，禁止产生第二套视觉验收规则。
- 本规则是 `TEST_APK` 和 `RELEASE_CLOSE` 的共同前置门禁，不把简单源码修复无理由升级为全版本关闭；只有准备生成 APK 候选时才运行完整 Android 自动化链。

## 10. Continuity GitHub 分层执行

- 每次 push/PR 都运行 `continuity_gate.py --mode ci --strict` 和 `check_v123_continuity.py --strict`，确保提交身份、Session、Checkpoint、Scope、CR、Trailer、Context Pack 与事实文件没有漂移。
- `scripts/continuity_ci_scope.py` 是完整生命周期选择器。仅当连续性策略、核心 CLI/库/门禁、自检脚本、Git Hook、运行时/传输描述、连续性回归测试或工作流自身发生变化时，运行临时 Git 仓库的交接、恢复、关闭、Clean Export 和篡改演练。
- Android/后端/Web 等普通产品变化，以及自动生成的 Session、Checkpoint、状态和 Context Pack 记录，不得单独触发完整连续性生命周期；核心轻量门禁仍不可跳过。
- 选择结果必须上传 `continuity-scope.json`。接续 AI 遇到失败先读取该文件区分 FAST 核心失败和 FULL 生命周期失败，不得无证据反复重跑整个工作流。
- Release 关闭门禁不得硬编码固定 operationId 数量；机器收尾允许版本未声明 operationId，但只要声明就必须全部非空、无重复且存在于权威 OpenAPI；生产验收至少声明一项并继续执行同一完整性校验。Android 候选 Commit 以 `android_delivery.source_commit`、APK Manifest 和候选报告三方一致为准，后续证据/文档关闭 Commit 与候选 Commit 分开追溯。Windows 运行门禁时依次使用 `HHY_GIT_BIN`、系统 PATH 和 Codex 捆绑 Git，禁止因 PATH 缺失误判 Git 历史或产生无意义失败。此规则不放宽 `owner_physical_test` 对正式 Release 验收和生产激活的硬门禁。
