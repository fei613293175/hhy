# P00 事件与账务不变量收口

- 状态：ACCEPTED（CR-0006 已独立审批并完成真实 PostgreSQL 17.10 复验）
- 日期：2026-07-17
- 关联：TASK-P00-002、ADR-002、ADR-003、CR-0006

## 背景

P00 的冻结表结构已包含 Outbox、Inbox、账务事实、余额投影和对账表，但旧迁移只覆盖了部分唯一约束、复式平衡与不可变触发器。实现审计发现：应用会话可自行打开旧的不可变写入开关，任意账务状态可绕过平衡校验，Outbox/Inbox/余额快照/对账生命周期也缺少可执行约束。

同时，冻结状态规范要求“对应状态历史表”，但 P00 的 198 表目录没有为本任务定义新的专用历史表；余额快照也没有账户正常余额方向或冻结明细来源字段。直接发明新表或余额语义会扩大冻结契约。

## 建议决策

1. 只新增前向迁移 `V010`，不修改已发布的 `V001..V009` checksum。
2. 会计交易表只保存已经入账的 `POSTED` 事实；草稿、审批和编排状态不得写入该事实表。交易及分录一经写入不可更新或删除，不再提供应用可控的绕过开关。
3. 冲正交易必须通过 `reversal_of_id` 唯一引用原交易；一个事实最多被完整冲正一次，且延迟约束在提交时校验其聚合分录与原交易逐账户、币种、方向完全相反。
4. Outbox 使用显式的发布、重试、死信和人工重放状态机；Inbox 通过 `consumer + message_id` 串行 claim，并同时核对 64 位小写 SHA-256，已完成结果不可覆盖。
5. `ledger_accounts`、`reconciliation_runs` 和 `reconciliation_differences` 的状态转换由数据库触发器限制。调用方仍必须使用旧状态或版本作为 `UPDATE` 条件；数据库行锁和转换守卫负责拒绝并发后的陈旧转换。
6. 在不增加第 199 张表的前提下，P00 四类状态改变以 `platform.status.changed.v1` 不可变 Outbox 事实保存。它是本任务的最小状态历史落点，不取代后续领域版本的专用历史表。
7. 余额快照的 `available_cent + frozen_cent` 必须等于指定分录游标前账户借贷净额的绝对值，游标必须属于同一账户且不得回退或在同游标改写金额。由于冻结契约没有正常余额方向和冻结来源，V010 不声明可用/冻结拆分各自可独立重建。
8. 同场景处于 `CREATED/RUNNING` 的对账时间窗不得重叠；对账批次和差异进入终态后不可改写。

## 保守边界

- 不实现 Outbox 发布器、消费者业务处理或对账调度器；它们分别属于后续 P00 服务任务。
- 不新增未登记的状态、表、列或金额方向规则。
- `V010` 回滚只允许用于一次性开发/测试库；生产环境一律以前向修复迁移纠错。
- CR-0006 已完成独立审批；任何后续语义扩张仍需新 CR 与前向迁移。

## 验证要求

真实 PostgreSQL 17.10 必须验证空库迁移、V009 升级、重复迁移 no-op、正反例 SQL、幂等并发冲突、对账窗口并发冲突、开发库 U010 回滚后再升级。静态 SQL 解析不能代替这些结果。
