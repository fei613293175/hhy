# R01 管理员认证安全不变量

- 状态：ACCEPTED
- 日期：2026-07-17
- 关联：TASK-R01-002、ADM-AUTH-001、ADM-AUTH-002、ADM-SECURITY-001

## 背景

V009 已登记管理员会话、MFA 方法、恢复码和登录安全日志，但主要是结构占位：会话可被降级或删除，MFA 状态没有可执行转换，恢复码缺少并发一次性消费边界，登录日志也没有不可变约束。`admin_users.mfa_secret_ref` 与 `admin_mfa_methods.secret_ref` 同时存在，若应用分别写入会产生双事实源漂移。

## 决策

1. 新增前向迁移 `V012`，不修改已发布的 `V002`、`V009` 或其 checksum。
2. `admin_mfa_methods` 是 MFA 密钥引用的唯一可写事实源。升级时迁移旧 `admin_users.mfa_secret_ref`，然后清空并约束旧列；旧列仅为冻结结构兼容，不再承载运行时事实。
3. 管理员会话必须使用 `version` 乐观并发更新；管理员身份、access jti 和创建时间不可改写，refresh hash 轮换与到期时间延期必须伴随版本递增，MFA 保证级别只能提升，吊销后进入终态且安全事实不可删除。
4. R01 API 仅开放冻结契约中的 `TOTP`，数据库保留后续已登记方法的兼容能力；方法执行 `PENDING -> ACTIVE/DISABLED`、`ACTIVE -> DISABLED`、`DISABLED -> PENDING` 状态机。禁用必须清除密钥引用；重新注册必须生成新引用；每次状态转换由应用服务在同一事务写入操作审计。
5. 恢复码只保存哈希，通过 `consume_admin_recovery_code` 原子消费。并发调用恰有一个返回成功，已使用或过期的恢复码失败关闭；事实不得删除或复用。
6. 管理员登录日志不可更新或删除，成功结果不得携带失败码；按管理员和 IP 建立失败窗口索引，供应用层按冻结配置计算锁定窗口。
7. `admin_operation_logs` 的冻结九字段不新增 `request_id`。R01 应用服务把 requestId 写入既有 `after_json` 审计载荷；认证事件仍使用 `admin_login_logs.request_id` 独立检索。

## 保守边界

- 不新增第 199 张表，不添加冻结目录以外的状态或列。
- 密钥引用只指向秘密管理服务，数据库不保存 TOTP 明文密钥或恢复码明文。
- 登录失败阈值和锁定秒数来自配置，数据库只保证日志事实可追溯且不可篡改。
- U012 仅用于一次性开发/测试库回滚；生产环境使用前向修复迁移。超过旧列 255 字符上限的密钥引用继续无损保留在规范化方法表，不回填或截断。

## 验证要求

必须在真实 PostgreSQL 上以单事务迁移验证空库、V011 升级到 V012、冲突升级全量回滚、正反例不变量、恢复码双消费者竞争、U012 回滚后重放 V012、长密钥引用无损、运行时迁移哈希一致和最终 198 表基线。
