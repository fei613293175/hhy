# R02 安全验证码弹层交互与视觉规格 V1.2.2

> 状态：`FROZEN_FOR_IMPLEMENTATION`
> 适用端：Android App；H5 邀请注册复用同一产品语义，具体 Web 组件另按 H5 Token 实现。
> 适用页面：`SCR-AUTH-001`、`SCR-AUTH-002`、`SCR-AUTH-003`、`SCR-AUTH-004`。
> 专用效果图：`design/effect-previews/B01-CAPTCHA/HHY_B01_CAPTCHA_8STATE_UI_REFERENCE.png`。
> API、字段和版本保持既有冻结契约不变；本文件只冻结用户可见 UI、流程编排和恢复行为。

## 1. 设计结论

### 1.1 最终承载形式

采用 **居中模态对话框（Centered Modal Dialog）**，不采用页面内联展开，也不采用默认底部弹层。

选择理由：

1. 安全验证码是原业务动作中的短时阻断步骤，不是独立页面，也不是可浏览的长内容。
2. 居中对话框能保留登录/注册表单上下文，同时明确阻断重复登录、重复短信发送和重复注册。
3. 与 B01 的协议弹层、强制更新弹层使用同一“深色遮罩 + 白色圆角卡片 + 蓝色主操作”视觉语言。
4. 输入、换图、错误和重试可在一个可控焦点域内完成，TalkBack 和键盘顺序明确。
5. 底部弹层容易被误认为可下滑关闭；键盘弹出后更容易遮挡验证码和按钮。页面内联方案则会显著推高表单并暴露技术状态。

不选方案及风险：

| 方案 | 不采用原因 |
| --- | --- |
| 页面内联展开 | 破坏四条认证流程的稳定布局；容易出现“创建安全验证”、challengeId、请求编号等技术信息；注册长表单在小屏上进一步失控。 |
| 默认底部弹层 | 容易被下滑或误触遮罩关闭；IME 弹出后可视高度不足；安全步骤的阻断感弱。 |
| 独立全屏页 | 打断原业务意图和返回栈；需要额外恢复表单、深链和导航状态；完成后还需用户重新确认原动作。 |

降级方案：当窗口可用宽度小于 `312dp`、横屏高度极低或系统无障碍字体造成内容超高时，仍使用同一 `Dialog` 语义，但内容区允许内部滚动；不切换为另一套业务页面。

## 2. 固定产品决策

1. 登录、注册、忘记密码页面初始状态 **不显示安全验证码组件**。
2. 页面上不得出现“创建安全验证”“生成挑战”等技术按钮。
3. 用户先完成当前业务动作所需的本地字段校验，再点击“登录”或“发送验证码”。
4. 客户端自动创建一次性挑战并打开弹层，用户无需理解后端挑战模型。
5. 验证成功后自动继续原业务意图，不要求再次点击登录或发送验证码。
6. `challengeId`、`token`、`clientNonce`、`deviceFingerprint`、Base64 和请求编号均不得显示。
7. 安全验证码答案、密码和短信码只在内存中短暂存在，不进入日志、埋点、URL、剪贴板历史或明文持久化。
8. 挑战由 `POST /api/v1/auth/security-challenges` 创建；没有新增独立“验证验证码”接口。
9. “验证并继续”会把答案随原业务请求一起提交：密码登录调用 `POST /api/v1/auth/password/login`；短信登录/忘记密码的发送动作调用 `POST /api/v1/auth/sms/send`；注册直接调用 `POST /api/v1/auth/register`。

## 3. 触发与自动续办矩阵

| 页面 | 用户原始动作 | 弹层前本地校验 | challenge scene | “验证并继续”提交的原业务请求 | 成功后的自动续办 | 取消/关闭后 |
| --- | --- | --- | --- | --- | --- | --- |
| `SCR-AUTH-001` 密码登录 | 点击“登录” | 手机号格式、密码规则、页面现有协议勾选及本地错误均通过 | `LOGIN` | `POST /api/v1/auth/password/login` | 显示短暂成功态后关闭弹层并进入登录成功导航；不得再次点击登录 | 保留手机号、当前内存中的密码和协议状态；清除挑战与答案；不发起登录 |
| `SCR-AUTH-002` 短信登录 | 点击“发送验证码” | 手机号有效、未处于短信冷却、无并行发送请求 | `LOGIN` | `POST /api/v1/auth/sms/send`，`scene=LOGIN` | 关闭弹层，启动短信倒计时，聚焦短信验证码输入框 | 保留手机号；清除挑战与答案；不发送短信 |
| `SCR-AUTH-003` 注册账号 | 点击“注册” | 手机号有效、密码符合规则、两次密码一致、邀请码非空 | `REGISTER` | `POST /api/v1/auth/register`，携带一次性挑战证明 | 显示短暂成功态后关闭弹层，保存登录会话并进入首页 | 保留手机号、密码、确认密码和邀请码；清除挑战与答案；不注册 |
| `SCR-AUTH-004` 忘记密码 | 点击“发送验证码” | 手机号有效、页面现有本地必填项无错误、未处于短信冷却 | `RESET_PASSWORD` | `POST /api/v1/auth/sms/send`，`scene=RESET_PASSWORD` | 关闭弹层，启动短信倒计时，聚焦短信验证码输入框；最终重置不重复弹图形验证码 | 保留手机号和新密码表单内存状态；清除挑战与答案；不发送短信 |

补充规则：

- 同一页面同一时刻最多存在一个 `PendingAuthIntent` 和一个挑战创建请求。
- 用户连续点击原业务按钮时，第二次及后续点击被忽略，不得并行创建多个挑战。
- 切换登录方式、离开页面或明确取消弹层时，当前挑战从 UI 状态中丢弃；再次操作必须创建新挑战。
- 短信已成功发送并进入倒计时后，不得因用户再次点击最终“登录/注册/重置”而重复要求图形验证码。

## 4. 页面与弹层结构

### 4.1 基准与尺寸

| 项目 | 数值 | 令牌/规则 |
| --- | ---: | --- |
| 设计基准宽度 | `360dp` | `layout.designBaselineWidthDp` |
| 弹层标准宽度 | `328dp` | 屏幕宽度减左右各 `16dp` |
| 弹层最小宽度 | `280dp` | `componentDp.dialogMinWidth` |
| 弹层最大宽度 | `360dp` | 平板和大屏仍保持短流程可读宽度 |
| 弹层高度 | 内容驱动 | 就绪态约 `360dp`；不得在代码中锁死固定高度 |
| 弹层最大高度 | `min(560dp, 可用高度 - 48dp)` | 超出后仅内容区滚动 |
| 圆角 | `20dp` | `radiusDp.dialog` |
| 阴影 | `elevation 8dp` | `elevationDp.dialog`、`shadow.dialog` |
| 水平内容内边距 | `24dp` | 现有 spacing token |
| 顶部内边距 | `24dp` | 现有 spacing token |
| 底部内边距 | `20dp` | 现有 spacing token |
| 遮罩 | `#182230`，`48%` | `opacity.scrim=0.48`；不叠加额外模糊 |
| Z 轴 | `dialog=1100` | `zIndex.dialog` |

### 4.2 组件顺序

```text
Dialog
├─ 关闭按钮（右上，48dp触控区 / 20dp图标）
├─ 标题：完成安全验证
├─ 场景副标题
├─ 挑战内容区
│  ├─ 图形验证码图片 / 加载骨架 / 错误占位
│  └─ 有效期提示 + 换一张
├─ 答案输入框
├─ 帮助 / 错误 / 过期 / 限流文案区（最少18dp高）
└─ 操作行
   ├─ 取消（84dp × 48dp）
   └─ 验证并继续（占剩余宽度 × 48dp）
```

### 4.3 验证码图片

| 项目 | 数值/行为 |
| --- | --- |
| 可见尺寸 | `216dp × 72dp` |
| 圆角 | `12dp` |
| 边框 | `1dp #E4E7EC` |
| 背景 | `#F5F7FA` 或图片自身背景 |
| 缩放 | 保持服务端图片比例，以 `Fit` 显示；不得裁掉字符 |
| 解码 | `imageBase64` 仅在内存解码，不落盘、不加入通用图片缓存 |
| 加载中 | 同尺寸骨架 + `24dp` 进度指示，不显示空白框 |
| 解码失败 | 显示“验证码图片加载失败”，提供“重新加载” |
| TalkBack | `图形验证码图片，请根据图片输入字符`；不得尝试朗读图片字符 |

### 4.4 有效期与刷新

- 有效期文案位于图片下方左侧，使用 `caption 12sp/18sp`，例如 `01:58 后失效`。
- 倒计时基于 `expiresAt` 和响应到达时的单调时钟偏移，不直接依赖用户可修改的墙上时钟。
- TalkBack 不每秒播报；只在剩余 `60s`、`30s`、`10s`、`5s` 和到期时播报。
- “换一张”为文字按钮，图标 `20dp`，整体触控区不小于 `48dp`。
- 主动刷新后立即清空答案、取消正在提交的旧答案状态，并用新的 `clientNonce` 和新的挑战创建幂等键请求新挑战。
- 刷新过程中保留弹层，图片区域显示骨架；“换一张”和“验证并继续”暂时禁用。
- 同一挑战刷新请求未结束前忽略重复刷新点击。

### 4.5 答案输入框

| 项目 | 数值/行为 |
| --- | --- |
| 高度 | `52dp`，沿用 `sizeDp.singleLineInputHeight` |
| 圆角 | `12dp`，沿用 `radiusDp.input` |
| 字号 | `14sp / 22sp / 400`，沿用 `typographySp.body` |
| 占位 | `请输入图中字符` |
| 键盘 | ASCII；关闭自动纠错、自动大写建议和系统 Autofill |
| 输入长度 | UI 最多保留 `32` 个可见字符；实际正确性由服务端验证，不在客户端猜测固定字符数 |
| 规范化 | 提交前仅去除首尾空白，不擅自改变大小写或字符内容 |
| 初始状态 | 空；主按钮禁用 |
| 错误状态 | `1dp #F04438` 边框，错误文案位于输入框下方；不只用颜色表达 |
| 持久化 | 可在同一进程和旋转期间保留于内存 ViewModel；不得写入 `SavedStateHandle`、磁盘、日志或埋点 |

### 4.6 按钮

| 按钮 | 尺寸 | 状态 | 文案 |
| --- | --- | --- | --- |
| 取消 | `84dp × 48dp`；圆角 `12dp`；白底灰边 | 加载、就绪、错误和网络失败时可用；提交已发出且结果未确认时按状态规则处理 | `取消` |
| 主按钮 | 高 `48dp`；占操作行剩余宽度；圆角 `12dp` | 答案非空且挑战有效时可用 | `验证并继续` |
| 主按钮加载 | 同尺寸，禁用重复点击 | 原业务请求进行中 | `验证中…` |
| 网络恢复按钮 | 同主按钮 | 创建挑战失败时可用 | `重新加载` |
| 结果未确认重试 | 同主按钮 | 原请求网络结果未知时，复用同一业务幂等键 | `重试` |

按钮文字使用 `15sp / 22sp / 600`；所有触控目标不小于 `48dp`。

## 6. 场景文案

| 场景 | 副标题 | 成功续办文案 |
| --- | --- | --- |
| 密码登录 | `请输入图中字符，验证通过后将继续登录` | `验证通过，正在登录…` |
| 短信登录 | `发送短信前，请先完成安全验证` | `验证通过，正在发送短信…` |
| 注册 | `请输入图中字符，验证通过后将继续注册` | `验证通过，正在继续注册…` |
| 忘记密码 | `发送重置短信前，请先完成安全验证` | `验证通过，正在发送短信…` |

通用文案：

| 状态 | 文案 |
| --- | --- |
| 挑战加载 | `正在为本次操作加载安全验证` / `请稍候…` |
| 输入帮助 | `自动忽略首尾空格；看不清可换一张` |
| 答案错误 | `输入不正确，请根据新图片重新输入` |
| 已过期 | `验证已过期，已为你换一张` |
| 图片失败 | `验证码图片加载失败` |
| 网络失败 | `网络连接失败，请检查后重试` |
| 限流 | `操作太频繁，请在 {seconds} 秒后重试`；倒计时取服务端返回，不自行编造 |
| 结果未知 | `请求结果暂未确认，请重试或稍后再操作` |
| 取消后的页面反馈 | 默认不弹 Toast；恢复原页面和原按钮可用状态 |

禁止文案：`创建安全验证`、`挑战ID`、`challengeProof`、`Token`、`Nonce`、`请求编号`、`Base64`。

## 7. 状态机

| 状态 | 进入条件 | 可见内容 | 可用操作 | 禁止操作 | 退出条件 |
| --- | --- | --- | --- | --- | --- |
| `HIDDEN` | 页面初始、用户取消或流程结束 | 原认证页面；不显示任何安全验证码区 | 原页面操作 | 不适用 | 原业务按钮通过本地校验后进入 `REQUESTING_CHALLENGE` |
| `REQUESTING_CHALLENGE` | 原业务按钮首次触发并开始创建挑战 | 模态弹层、标题、副标题、进度、取消 | 取消 | 重复创建、提交答案、切换页面内业务动作 | 创建成功进入 `READY`；失败进入 `NETWORK_ERROR` / `RATE_LIMITED` |
| `READY` | 图片已解码、答案为空 | 图片、有效期、换一张、空输入框、禁用主按钮 | 输入、刷新、取消 | 提交空答案 | 输入后进入 `INPUTTING`；到期进入 `EXPIRED_REFRESHING` |
| `INPUTTING` | 答案非空且挑战未过期 | 完整就绪弹层，主按钮可用 | 编辑、刷新、取消、验证并继续 | 重复并行提交 | 点击主按钮进入 `SUBMITTING_INTENT` |
| `SUBMITTING_INTENT` | 以当前挑战和答案提交原业务请求 | 输入和刷新禁用，主按钮 `验证中…` | 结果未知时按恢复规则重试；系统返回键默认禁用至请求得到可判断结果 | 重复登录、重复发短信、修改答案 | 业务成功进入 `SUCCESS_CONTINUING`；挑战错误进入 `WRONG_ANSWER`；其他业务错误关闭弹层回页面；网络未知进入 `NETWORK_ERROR` |
| `WRONG_ANSWER` | 现有 `ErrorResponse.details.field=challengeProof` 或等价挑战错误语义 | 错误文案；答案清空；自动请求新图片 | 取消；新图就绪后重新输入 | 继续提交旧挑战 | 新挑战成功后回 `READY`；刷新失败进入 `NETWORK_ERROR` |
| `EXPIRED_REFRESHING` | `expiresAt` 到期、应用恢复时已过期或服务端返回挑战过期 | 警告文案、图片骨架；答案立即清空 | 取消 | 提交旧答案、复用旧 challengeId | 新挑战成功后进入 `READY` |
| `NETWORK_ERROR` | 创建挑战、图片解码或原业务请求发生离线、超时、5xx | 原位错误说明和恢复按钮；主表单仍被遮罩保护 | 重新加载/重试、取消（原业务结果未知时须先显示风险提示） | 自动无限重试、创建并行挑战 | 恢复成功后进入相应状态；取消进入 `HIDDEN` |
| `RATE_LIMITED` | 创建挑战或原业务请求返回 `429` | 限流说明、服务端倒计时、禁用主按钮 | 取消；倒计时结束后重试 | 提前重试 | 计时结束后回 `REQUESTING_CHALLENGE` 或 `READY` |
| `SUCCESS_CONTINUING` | 原业务请求已成功，说明挑战也已通过 | 成功图标、结果文案、短时进度 | 无需用户再次点击 | 返回、重复提交 | 保持 `360ms` 后退出 `120ms`，关闭弹层并执行导航/短信倒计时 |
| `CANCELLED` | 点击关闭、取消或系统返回 | 不单独展示 | 原页面继续编辑 | 自动续办原动作 | 立即清除挑战、答案和待处理意图后进入 `HIDDEN` |

### 7.1 原业务错误与挑战错误分离

- 如果错误详情明确指向 `challengeProof`、挑战过期或挑战冲突，弹层负责恢复。
- 如果密码错误、手机号未注册、邀请码状态、短信通道规则等 **不是挑战本身的问题**，清除一次性挑战并关闭弹层，由原页面按既有错误映射显示；不得把“账号或凭证不正确”错误展示成“验证码错误”。
- 该分离使用现有 `ErrorResponse.error.details` 通用结构，不增加 API 字段。

## 8. 弹出、关闭和返回行为

| 操作 | 行为 |
| --- | --- |
| 点击遮罩 | **不关闭**，无副作用；避免误触导致用户不理解为何登录未继续 |
| 点击右上关闭 | 取消当前安全验证，保留主表单，清除挑战/答案/待处理意图 |
| 点击“取消” | 与关闭按钮相同 |
| 系统返回键 | `REQUESTING_CHALLENGE`、`READY`、`INPUTTING`、`WRONG_ANSWER`、`EXPIRED_REFRESHING`、可判断的 `NETWORK_ERROR` 中等同取消；`SUBMITTING_INTENT` 在结果未确认前不直接关闭 |
| 切到后台 | 保留内存状态；回前台时比较 `expiresAt`，过期则自动换图并清空答案 |
| 进程被杀 | 不恢复答案、token 或挑战；返回页面后弹层为隐藏状态，用户重新触发 |
| 横竖屏切换 | 同一进程内可保留未过期挑战和答案于 ViewModel 内存；不得写入持久化 SavedState |

## 9. 动画与时序

| 动画 | 参数 |
| --- | --- |
| 遮罩进入 | `200ms`，标准 easing，透明度 `0 → 0.48` |
| Dialog 进入 | `200ms`，`alpha 0→1`、`scale 0.96→1`，`easing.standard` |
| Dialog 退出 | `120ms`，`alpha 1→0`、`scale 1→0.98` |
| 加载/就绪/错误内容切换 | `120ms` Crossfade；Dialog 外框位置不跳变 |
| 换图 | 旧图 `80ms` 淡出，骨架，新的图片解码后 `160ms` 淡入 |
| 答案错误 | 输入框水平震动总计 `240ms`，最大位移 `4dp`；同时显示文字错误 |
| 成功 | 成功图标进入 `200ms`；文案停留 `360ms`；Dialog 退出 `120ms`；随后导航或开始短信倒计时 |
| 减少动画 | 系统开启“移除动画”时取消缩放和震动，仅保留不超过 `120ms` 的透明度切换 |

自动续办时序：

```text
用户点击原业务按钮
→ 本地校验
→ Dialog进入 + 创建挑战
→ 用户输入答案
→ 点击验证并继续
→ 使用答案提交原业务请求
→ 成功确认360ms
→ Dialog退出120ms
→ 登录导航 / 短信倒计时与焦点迁移
```

## 10. 键盘、小屏和无障碍

### 10.1 IME 与小屏

- 可用高度 `≥600dp` 且字体比例 `≤1.15` 时：图片解码成功后延迟 `120ms` 请求答案输入焦点并打开键盘。
- 可用高度 `<600dp`、字体比例 `≥1.30`、横屏或分屏时：不强制弹键盘；用户点击输入框后打开。
- Dialog 使用 `WindowInsets.ime` 和安全区计算可用高度；与 IME 至少保留 `12dp` 间距。
- 超高内容仅在 Dialog 内部纵向滚动；标题和操作按钮在可实现时保持可见，否则由 `BringIntoViewRequester` 保证当前输入框和主按钮可达。
- 不允许通过缩小验证码、文字小于 Token 或按钮低于 `48dp` 来适配小屏。

### 10.2 焦点顺序

```text
关闭按钮
→ 验证码图片
→ 换一张
→ 答案输入框
→ 错误/帮助说明
→ 取消
→ 验证并继续
```

### 10.3 TalkBack

- Dialog 打开时播报：`完成安全验证。{场景副标题}`。
- 图片：`图形验证码图片，请根据图片输入字符`。
- 刷新：`更换验证码图片`。
- 输入错误区设置为 `LiveRegionMode.Assertive`，只播报一次。
- 成功态播报：`验证通过，正在继续`。
- 所有图标都有可读标签；不能只用颜色、图标或动画表达状态。
- 字体比例 `1.0 / 1.15 / 1.30` 必须通过截图回归和可操作性测试。

## 11. API 字段与 UI 内部绑定

| 既有字段 | 内部用途 | 用户可见映射 | 禁止事项 |
| --- | --- | --- | --- |
| `scene` | 创建对应登录/注册/重置场景挑战 | 仅影响副标题，不直接显示枚举值 | 不显示 `LOGIN/REGISTER` 等技术枚举 |
| `clientNonce` | 防重放的客户端随机值 | 无 | 不显示、不记录明文 |
| `deviceFingerprint` | 风险判断 | 无 | 不显示、不放入普通日志/埋点 |
| `challengeId` | 当前一次性挑战标识 | 无 | 不显示请求编号或 UUID |
| `challengeType` | 选择图形或未来 Provider 容器 | 无技术文案；首版渲染图形验证码 | 不显示类型名 |
| `expiresAt` | 计算有效期 | `01:58 后失效` 等用户文案 | 不显示原始 ISO 时间 |
| `imageBase64` | 内存解码图片 | 图形验证码图片 | 不显示 Base64，不落盘 |
| `token` | 第三方/未来 Provider 内部令牌 | 无 | 不显示、不缓存、不日志 |
| 用户答案 | 后续原业务请求的 `challengeProof` | 答案输入框 | 不写日志、URL、埋点或持久化 |
| `X-Idempotency-Key` | 防重复创建挑战和防重复原业务请求 | 无 | 不显示、不复用到不同请求体 |

重要说明：页面规格表中 `challengeId`、`imageBase64`、`token` 等“主要内容/显示”行表示响应数据绑定能力，不代表用户可见控件。本文件是这些字段的 UI 展示覆盖规则：只显示验证码图片、有效期和人类可读状态，永远不显示原始技术值。

## 12. 错误与恢复矩阵

| 场景 | 可见反馈 | 恢复动作 | 表单保留 |
| --- | --- | --- | --- |
| 本地手机号/密码等未通过 | 不打开 Dialog；原页面字段就地报错 | 用户修改原字段 | 保留 |
| 创建挑战 `400/422` | `暂时无法创建安全验证，请重试` | 重新加载或取消 | 保留全部主表单 |
| 挑战答案错误 | 输入框红边；`输入不正确，请根据新图片重新输入`；自动换图 | 输入新答案 | 保留主表单；旧答案清空 |
| 挑战过期 | `验证已过期，已为你换一张` | 等新图就绪后输入 | 保留主表单；旧答案清空 |
| 挑战冲突 `409` | 视为当前挑战失效，不展示技术冲突 | 自动新建挑战 | 保留主表单 |
| 频率限制 `429` | `操作太频繁，请在 N 秒后重试` | 倒计时结束后恢复 | 保留 |
| 离线/超时/5xx（创建阶段） | `网络连接失败，请检查后重试` | `重新加载` 或取消 | 保留 |
| 图片解码失败 | `验证码图片加载失败` | `重新加载` | 保留 |
| 原业务请求传输结果未知 | `请求结果暂未确认` | 请求体不变时复用同一业务幂等键重试；不得并行创建新挑战 | 保留；不清除页面输入 |
| 原业务非挑战错误 | 关闭 Dialog，由原页面按既有规则显示，例如账号凭证错误、手机号未注册 | 用户按原页面修正 | 保留页面允许保留的内存输入；挑战清除 |
| 用户取消 | 不显示错误 Toast | 再次点击原业务按钮重新开始 | 保留主表单；挑战和答案清除 |

## 13. 安全、日志和埋点

允许记录的状态型事件：

- `auth_security_dialog_opened`：仅记录 `scene`、入口页面和匿名会话上下文。
- `auth_security_challenge_loaded`：仅记录耗时区间、成功/失败和挑战类型类别。
- `auth_security_refresh_clicked`：仅记录次数，不记录图片或答案。
- `auth_security_submit_result`：仅记录结果类别 `SUCCESS / WRONG / EXPIRED / RATE_LIMITED / NETWORK / BUSINESS_ERROR`。
- `auth_security_cancelled`：仅记录取消来源 `close / cancel / back`。

绝对禁止记录：

- 答案内容、密码、短信验证码、手机号原文；
- `challengeId`、`token`、`clientNonce`、`deviceFingerprint`；
- 图片 Base64、图片像素、剪贴板内容；
- 请求体和响应体的敏感原文；
- 将上述值写入崩溃报告、自定义埋点、URL、Toast 或截图文件名。

## 15. 测试与验收

### 15.1 UI 与截图

- 360dp 基准、320dp 小屏、横屏、分屏分别验证。
- 字体比例 `1.0 / 1.15 / 1.30` 截图回归。
- P01—P08 与 `HHY_B01_CAPTCHA_8STATE_UI_REFERENCE.png` 做布局和状态对照。
- 验证 Dialog 圆角 `20dp`、输入/按钮 `12dp`、遮罩 `48%`、触控区 `48dp`。

### 15.2 四条业务路径

- 密码登录：验证成功只提交一次登录并正确导航。
- 短信登录：验证成功只发送一次短信，倒计时和焦点正确。
- 注册：点击“注册”后触发；验证通过后自动提交注册，不发送注册短信。
- 忘记密码：发送重置短信前触发；最终重置不重复弹图形验证码。

### 15.3 状态与并发

- 初始页永远不出现安全验证码或“创建安全验证”。
- 连续点击原业务按钮只创建一个挑战。
- 连续点击“验证并继续”只产生一个原业务请求。
- 主动刷新、答案错误、到期和前后台恢复均清除旧答案并使用新挑战。
- `429` 使用服务端倒计时；倒计时期间不发请求。
- 网络结果未知时复用同一幂等键，不并行提交。
- 取消、关闭、返回均保留主表单且不自动续办。

### 15.4 无障碍与安全

- TalkBack 焦点顺序、文案和错误 Live Region 通过。
- 键盘打开后输入框和操作按钮可达。
- 减少动画模式不执行缩放和震动。
- 日志、埋点、崩溃报告、本地存储和截图文件中搜索不到答案、Base64、token、Nonce、设备指纹和密码。
- 进程重建后不恢复挑战答案或内部 token。

## 16. 开发约束摘要

```text
初始隐藏
→ 点击真实业务按钮
→ 自动创建挑战
→ 居中Dialog输入
→ 验证并提交原业务请求
→ 成功自动续办
```

以下实现均视为不符合本规格：

- 页面内联验证码；
- “创建安全验证”技术按钮；
- 显示 challengeId、Token、Nonce、Base64 或请求编号；
- 验证成功后要求用户再次点击登录/发送验证码；
- 点击遮罩直接关闭；
- 错误后清空手机号、密码、邀请码或协议状态；
- 以固定高度截断大字体/小屏内容；
- 为图形验证码新增未经批准的 API 或独立页面。
