# UI 参考图使用与开发约束 V1.2

## 核心结论

12 批组合效果图已经纳入项目，它们的工程地位是：

> **效果图是页面建模、布局、视觉风格、信息层级和组件摆放的强制来源，但不是功能事实源。**

开发功能、字段、动作和正式文案必须来自完整项目开发文档、业务规则、API 契约、数据库模型和测试用例。精确 UI 数值必须来自 Design Token、页面规格和组件目录。开发者或 AI 不得把效果图理解为可自由发挥的灵感图。

视觉完成标准不仅是“参数正确、页面能用”。在移除效果图中的虚构业务后，正式页面仍必须让人肉眼感受到与参考图同等级的信息密度、层级丰富度、组件细节、品牌质感和状态完整性。过度留白、只有基础 Material 控件、缺少参考图中的合法视觉层次或整体明显粗糙时，即使字号、边距和接口全部正确，也只能登记为待重构，不能判 `PASS`。

## 冲突优先级

1. 完整项目开发文档
2. 已批准 Change Request / ADR
3. Design Token
4. 页面规格和组件规范
5. 屏幕—效果图绑定表
6. 12 批效果图
7. 开发者或 AI 推测

## Codex 禁止行为

- 根据效果图中的虚拟按钮新增功能。
- 根据效果图中的虚拟金额、会员类型、余额或文案修改业务规则。
- 因效果图没有画某功能而删除开发文档要求。
- 使用效果图像素写死所有高度和位置。
- 直接复制 AI 生成的错误中文。
- 在页面中自行创造未登记颜色、dp、sp、圆角和阴影。
- 在有精确效果图或补充视觉规格时自行增加 Hero、卡片、分栏、导航、表单区块或改变组件位置。
- 用 Material、浏览器或组件库默认字号、默认高度、默认圆角代替已经冻结的 Design Token。
- 使用 `P01-P08`、`TOKENS_ONLY`、相邻页面风格等粗粒度绑定直接进入 UI 编码。
- 因过滤效果图中的虚拟功能或无关文字而重新设计其余页面结构。
- 用“没有足够真实字段”为由把页面退化成稀疏的标题、输入框和单卡片；应使用合同内真实字段、合法空态、装饰性非业务资产和批准组件恢复视觉层级，但不得虚构业务事实。
- 以自动截图存在、像素稳定、Token检查通过或功能旅程成功代替肉眼丰富度与精致度对照。
- 在没有精确效果图或批准补充视觉规格时猜测页面布局并交付 APK。
- 将 B09 中的“充值/商豆”实现为用户充值钱包。
- 将 B11 中的多种会员身份实现为多套会员体系。
- 将 B01 中的第三方登录图标实现为微信/QQ/支付宝登录。

## 开发应还原的内容

- 页面区域顺序
- 信息主次层级
- 卡片形态
- 导航和按钮位置
- 表单区块组织
- 空状态、成功、失败、弹层的视觉关系
- 合伙云品牌色和统一组件语言

以上内容是必须还原项，不是可选参考。只有逐页视觉合同明确登记为虚拟/无关业务的元素可以删除或替换；未登记的区域顺序、信息层级、布局和样式不得改变。

删除虚构元素后必须优先用同一页面合同允许的真实信息、公开装饰资产、状态说明或空间组织完成等价视觉映射。若仍无法达到参考完成度，先复用相近页面的已批准视觉语言；无法可靠复用时，生成“效果图补充需求包”，列明页面目标、真实字段、禁止虚构项、必需状态、相近参考和期望输出，交由项目所有者在 ChatGPT 网页端补图。补图经 CR 批准后继续进入本规则与同一验收目录，不建立第二套 UI 规则。

## 精确数值

固定值见 `design/tokens/hhy_design_tokens_v1.2.2.json`。包括：

- 页面左右边距 16dp
- 模块间距 20dp
- 卡片间距 12dp
- 卡片内边距 16dp
- 顶部导航 56dp
- 底部导航 64dp + 安全区
- 主按钮 48dp
- 输入框 52dp
- 卡片圆角 14–16dp（具体组件固定一种）
- 按钮/输入框圆角 12dp
- 页面标题 20sp/28sp
- 卡片标题 16sp/24sp
- 正文 14sp/22sp

页面不得从效果图重新估算这些数值。

## 已知视觉偏差

- B01：图中以短信登录为主且出现第三方登录；真实产品默认手机号+密码登录，不实现第三方登录。
- B09：图中出现钱包充值和商豆；真实产品无用户充值钱包、无商豆，仅有奖励账户、收益明细和提现。
- B10：图中出现商家余额、线索 CRM 和商家套餐；只复用工作台、列表和数据看板布局，不自动增加这些功能。
- B11：图中出现普通会员、商家会员、团队长 Pro；真实产品只有一种 Pro 会员，月/季/年只是期限 SKU。
- 所有图片中的金额、日期、人数、收益、分类、标签和文案均为占位数据。

## 绑定规则

`catalogs/screen_visual_binding.csv` 只负责候选参考索引。每个进入实现或修改的页面还必须在 `catalogs/ui_visual_acceptance.csv` 建立逐页视觉合同，至少记录：

- Screen ID
- 所属 Release、平台和页面名称
- 一个或多个精确效果图面板，或批准的补充视觉规格
- 页面建模与布局还原要求
- 需要过滤、删除或替换的虚拟功能、无关文字和占位数据
- Design Token 来源和实现路径
- 参考图证据、真机/浏览器截图证据和验收状态
- 肉眼丰富度、信息层级、组件精致度、真实业务映射和历史回补状态

以下绑定不得作为施工合同：`P01-P08` 等面板范围、`TOKENS_ONLY`、仅写批次不写面板、仅参考相邻组件。

若无精确面板，必须先通过批准 CR 增加补充视觉规格；在规格批准前，该页面状态只能是 `BLOCKED_VISUAL_SPEC`，不得编写或交付自行构思的正式 UI。

## 逐页施工与验收顺序

1. 从页面规格确认功能、字段、状态、动作和正式文案。
2. 在逐页视觉合同中绑定精确效果图面板或批准的补充视觉规格。
3. 明确登记效果图中需要过滤、删除或映射的虚拟业务元素。
4. 按效果图还原建模、区域顺序、信息层级、布局、对齐、组件形态和视觉样式。
5. 按 Token/组件规格落地字号、行高、间距、宽高、圆角、颜色、阴影、遮罩、动画与响应式。
6. 运行 Token 静态门禁和页面自动化测试。
7. 提交真机或浏览器截图，与参考图逐项核对并把状态改为 `PASS`。
8. AI 必须明确给出肉眼对照结论；结论至少覆盖信息密度、层级、组件细节、品牌质感和状态完整性，并证明视觉内容来自真实合同而非虚构业务。

缺少任一步，页面不得标为完成；所属版本不得关闭。

P00、R01–R08 的既有前端页面按同一目录重新审计，旧截图和旧状态只作为历史证据；未完成新标准回补前不得声称历史 UI 已达到效果图级质量。全局整改统一执行 `python scripts/check_ui_visual_acceptance.py --historical-through R08`，其结果阻断“历史 UI 全部整改完成”的声明，但不追溯推翻已经完成的 R08 机器收尾。按项目所有者确定的顺序，R08 机器收尾后必须先完成该轮全局审计和必要返工，再进入 R09 新业务页面施工；无依赖的非页面工作可继续。
