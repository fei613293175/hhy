# 无状态接续、开发记录与需求变更协议 V1.2

## 核心原则

聊天不是项目事实源。任何正式需求、修改、决策、问题、经验和进度都必须提交Git。新AI只需仓库和一句“请继续开发这个项目”，即可读取状态、生成上下文包、执行项目体检并从 `NEXT_TASK.yaml` 继续。

## 用户提出修改时的强制流程

1. AI判断是否改变已冻结需求；若是，先运行 `scripts/create_change_request.py` 创建 `CR-XXXX`。
2. CR记录用户原话摘要、原规则、新规则、页面/API/表/配置/测试/版本影响、迁移和兼容方案。
3. 更新主文档、需求目录、追踪矩阵、Changelog、Release Manifest和测试。
4. 经用户确认后才编码；不得只在聊天中确认后静默修改。
5. 完成后Session Log关联CR、Commit和PR。

## 每次开发结束必须更新

- `CURRENT_STATUS.yaml`
- `NEXT_TASK.yaml`
- `docs/03-continuity/sessions/SES-*.md`
- `PROBLEM_REGISTRY.yaml`（发现或解决问题）
- `REUSABLE_PATTERNS.md`（成熟方案）
- `PITFALLS.md`（踩坑和禁止做法）
- `CHANGELOG.md`
- `TRACEABILITY_MATRIX.csv`
- 相关Release Manifest、契约和测试

## 已解决问题不得重复分析

开始任务前按模块搜索 Problem Registry、ADR、Change Request和Reusable Patterns。已标记SOLVED且有回归测试的问题，除非出现新证据，不得重新设计另一套方案。

## 冷启动接手门禁

P00、每5个版本、重大架构变更后和R32前，用全新AI会话只提供仓库并说“请继续开发这个项目”。必须正确识别当前版本、任务、已知问题、构建测试方法和下一步；失败视为工程缺陷。
