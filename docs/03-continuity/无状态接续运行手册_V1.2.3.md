# 无状态接续运行手册 V1.2.3

## 1. 首次导入

```bash
python3 scripts/continuity.py bootstrap \
  --actor ai-codex-platform-01 \
  --init-git --initial-commit \
  --task TASK-P00-001 \
  --branch task/TASK-P00-001
```

该命令原子完成 Git 初始化、受控基线 Commit、Hook 安装、Commit 模板和任务分支。不要手工拆分这些步骤。

## 2. 日常冷启动

```bash
python3 scripts/continuity.py resume
```

严格按输出执行 `start`、`takeover` 或 `recover`。不要在运行前修改文件。

随后验证已连接的项目云服务器与既有环境：

```bash
python3 scripts/verify_cloud_environment.py --check-android
```

除非项目所有者明确报告未连接，否则必须假定 Codex 已连接 `obx-test` 且项目环境已经存在。预检失败时阻断并报告；不得把失败、换电脑或换 AI 当作无服务器开发许可，也不得下载、安装或重建本地 Android SDK。Android 只能复用 `hhy-android-toolchain:r01-46fb273` 和 `hhy-r01-android-gradle-cache`。

## 2.1 模型分级

每个工作包按实际复杂度选择模型，并把目标模型、实际模型、推理等级和回退原因写入可审计记录：

```bash
python3 scripts/select_execution_profile.py --complexity complex --available-model Sol --available-model Terra
python3 scripts/select_execution_profile.py --complexity medium --available-model Sol --available-model Terra
python3 scripts/select_execution_profile.py --complexity light --available-model Sol --available-model Terra
```

- 复杂/高风险：Sol。
- 中等：Terra。
- 轻量、机械或只读：Luna。
- Luna 不可用时：Terra low，并记录 `LUNA_UNAVAILABLE_FALLBACK`；禁止声称使用了 Luna。

## 2.2 跨电脑 Git 恢复

`config/REPOSITORY_TRANSPORT.yaml` 是 remote/upstream 的非秘密事实源。PAT、SSH 私钥/路径、Credential Helper 输出和完整 `.git/config` 不得进入仓库、交接包或日志。

先只读查看状态：

```bash
python3 scripts/restore_git_transport.py status
```

三种合法恢复路径：

```bash
# 正常 clone 或保留 .git 的 Handoff：验证并恢复当前目录的 origin/upstream
python3 scripts/restore_git_transport.py restore --root . --branch task/<TASK_ID>

# 已验证 repository.bundle：恢复到新目录并重建 origin/upstream
python3 scripts/restore_git_transport.py restore --bundle repository.bundle --target <TARGET_DIR> --branch task/<TASK_ID>
```

无 `.git` 且无已验证 `repository.bundle` 的纯源码包必须阻断，不得伪造历史或覆盖远端。remote 不匹配时只有显式 `--allow-remote-repair` 才可按 descriptor 修复；认证由新电脑本机的 Credential Manager 或 SSH Agent 提供。

## 3. 领取任务

```bash
python3 scripts/continuity.py start \
  --actor ai-codex-platform-01 \
  --task TASK-P00-001 \
  --story STORY-P00-002 \
  --goal '实现精确目标'
```

## 4. 检查点

有变更时必须记录测试：

```bash
python3 scripts/continuity.py checkpoint \
  --summary '本阶段实际完成' \
  --next-step '下一步精确到文件/测试' \
  --test 'continuity doctor|PASS|artifacts/validation/report.json|通过'
```

当前阶段不能测试时：

```bash
python3 scripts/continuity.py checkpoint \
  --summary '仅完成接口骨架' \
  --next-step '补实现后执行契约测试' \
  --no-test-reason '当前尚无可执行实现；对应测试已登记'
```

NOT_RUN 不能用于任务完成关闭。

## 5. 提交

```bash
git add -A
git commit -m 'feat(scope): precise summary'
```

Hook 自动加 `[STORY/TASK]` 和 Trailer。禁止只暂存部分项目文件。检查点后继续修改必须重新检查点。

## 6. 冻结事实变更

```bash
python3 scripts/continuity.py cr-create \
  --actor ai-codex-platform-01 --title '<标题>' \
  --task TASK-... --user-request '<用户需求>' --reason '<原因>'

python3 scripts/continuity.py cr-amend \
  --actor ai-codex-platform-01 --cr CR-.... \
  --original-rule '<原规则>' --new-rule '<新规则>' \
  --impact-summary '<影响摘要>' \
  --migration-and-compatibility '<迁移和兼容策略>' \
  --file 'contracts/openapi.yaml' \
  --test 'contract compatibility test' \
  --release 'Rxx'

python3 scripts/continuity.py cr-approve \
  --actor human-techlead-02 --cr CR-.... \
  --decision APPROVED --note '<审批说明>' \
  --user-confirmation '<用户确认依据>'
```

申请人不能审批自己；不完整 CR 不能批准。

## 7. 长任务续租

```bash
python3 scripts/continuity.py heartbeat \
  --actor ai-codex-platform-01 --note '正在执行长时间构建'
```

Heartbeat 只延长短期运行租约，不替代检查点。

## 8. 中途换 AI

```bash
python3 scripts/continuity.py checkpoint ...
python3 scripts/continuity.py handoff \
  --actor ai-codex-platform-01 --reason '切换AI' \
  --next-step '接管后第一步' --portable-zip handoff.zip
```

新 AI：

```bash
python3 scripts/continuity.py resume
python3 scripts/continuity.py takeover \
  --actor ai-codex-platform-02 \
  --session SES-... --reason '接管已验证交接包'
```

## 9. 异常恢复

```bash
python3 scripts/continuity.py recover \
  --actor ai-codex-platform-02 --session SES-... \
  --reason '原执行者异常中断且租约已过期' \
  --next-step '重新验证WIP并建立检查点'
```

租约未过期不能强占。

## 10. 完成任务

先提交实现内容并建立 PASS 检查点，然后：

```bash
python3 scripts/continuity.py close \
  --actor ai-codex-platform-02 \
  --result COMPLETED \
  --summary '完成摘要' \
  --next-task TASK-...

git add -A
git commit -m 'chore(continuity): close completed task'
python3 scripts/restore_git_transport.py push-preflight
git push
```

`close` 输出的关闭检查点和 Trailer 必须进入最后元数据 Commit。

## 11. 干净项目导出

```bash
python3 scripts/continuity.py export-clean \
  --portable-zip project-handoff.zip
```

只适用于会话关闭和工作区干净状态。
