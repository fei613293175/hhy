# CR-0156 — 延长CI一次性引导码至覆盖确定性模拟器冷启动

## 用户需求摘要

项目所有者要求减少GitHub反复耗时、自动登录高效稳定并持续开发

## 原规则

CI一次性引导码固定两分钟到期，GitHub在模拟器冷启动和测试APK编译前签发

## 新规则

一次性引导码改为十分钟硬上限，仍绑定仓库、工作流、Commit与Run并在事务内单次消费；短时登录会话仍为十五分钟，生产环境继续硬拒绝

## 修改原因

R06候选实证显示引导码签发后3分24秒才兑换，冻结2分钟TTL必然过期并使会话接口返回500

## 影响摘要

只扩大GitHub候选冷启动覆盖窗口，不引入密码或长期凭据；修复确定性过期500并保留单次消费和生产隔离
