# CR-0455 — 替代CR-0454封死全部跨版本续接旁路

## 用户需求摘要

总结R14未完成却跳过R15进入R16的连续性错误根因，并强制更新既有规则与机器门禁；开发不得依赖聊天记录。

## 原规则

既有规则允许TEST_APK或候选失败后继续下一独立Release；continuity跨Release只看依赖，start与冷resume只信状态指针，ACTIVE resume、HANDED_OFF takeover、过期recover均未交叉核验直接前序Release；Android自动化规则还明确candidate失败不阻断下一版。

## 新规则

R14起下一业务Release只能是当前Release编号+1；owner真机PENDING异步非阻断，但上一Release必须全部TASK完成（close仅把本次COMPLETED的当前最终TASK拟DONE）、同一冻结Commit的TEST_APK与测试文档/Manifest/Evidence身份一致、同Release同Commit GitHub真实交互候选PASS、machine completion PASS后才能进入。candidate FAIL/缺失、任务未完、证据缺失或身份错配、R14直跳R16均硬失败。统一仓库证据门禁必须在任何写入前覆盖start、无会话和有会话resume、close、takeover、recover；CURRENT_STATUS/NEXT_TASK/现有Session均不能单独证明完成。发现历史错误会话只能在明确的sequence-recovery流程中退回最近未完成Release，不得继续目标Release业务代码。R13及以前owner异步尾部只保留历史兼容。

## 修改原因

CR-0454已独立REJECTED并保留历史：虽覆盖冷resume/start/close，但ACTIVE resume、HANDED_OFF takeover和过期recover仍可继续错误R16会话；本CR补齐全部入口。

## 影响摘要

完整原位统一连续性、Android自动化、测试体系与效率规则；新增唯一版本序列/机器闭环验证器并接入start/resume(active与cold)/close/takeover/recover，所有失败零写入；登记问题、踩坑、复用模式，当前恢复顺序固定R14、R15、R16。
