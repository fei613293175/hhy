# CR-0316 — 实现R12统一发布管理数据库状态机与领域不变量

## 用户需求摘要

按仓库R01-R32计划持续完成合伙云Pro；R12统一发布、草稿、审核、上下架、复制和无自动过期必须与冻结开发文档一一对应。

## 原规则

V007仅约束CONTENT_STATUS枚举；V029-V038覆盖类型匹配、垂直详情和历史不可变，但枚举内非法跳转、无初始历史、状态变化缺少同版本历史/审核/快照/Outbox绑定、PROJECT活动详情缺失、联系方式空值/顺序/渠道重复、媒体重复以及DELETED后子数据或媒体对象级联删除仍可发生。冻结DELETE合同缺少expectedVersion，ContentService错误允许OFFLINE_BY_PLATFORM直接ONLINE。

## 新规则

V039/U039继续以V007枚举和database/state_machines.yaml为唯一状态机，并由check_content_state_machine_projection.py逐边校验SQL投影完全一致；通配BAN/DELETE不得从DELETED、BANNED继续迁移或自迁移。新内容只能DRAFT/version=0并由数据库自动写NULL到DRAFT初始历史；任何业务或状态更新version必须恰好+1。content_status_logs新增transition_version并按(content_id,transition_version)唯一。content_review_records新增snapshot_version_id外键绑定content_versions.id以及command_id；同一快照允许CLAIM、ASSIGN、APPROVE或REJECT多条不可变记录，仅按(content_id,command_id)保证命令幂等。提交/重提必须有当前乐观版本的不可变快照，审核迁移必须存在绑定该提交快照的对应审核记录。创建、业务更新和每次状态迁移必须同事务写CONTENT Outbox，数据库向payload注入并校验contentVersion。非DELETED内容恰有一份匹配类型详情；任何状态下均禁止物理删除详情、媒体、联系方式、版本、审核和历史，内容媒体的media_objects级联同样被子表删除守卫阻断，真正清理由未来批准的保留策略迁移处理。V039先审计并验证旧NULL/空渠道、非法顺序、重复值和NOT VALID约束，再新增(content_id,sort_order)联系方式全局顺序唯一、(content_id,channel)渠道唯一、(content_id,media_id)媒体唯一。DELETE /api/v1/contents/{id}增加必填expectedVersion查询参数并同步运行时合同、生成客户端、动作/字段目录与SCR-MYC-002施工规格；该操作尚无运行时控制器或已发布消费者，属于首次实现前冻结合同纠错。ContentService禁止OFFLINE_BY_PLATFORM直接ONLINE。TASK-R12-003复制命令复用既有idempotency_records唯一领取和首次响应快照，目标为新ID、DRAFT/version=0，源不变，同键并发仅创建一个目标并重放首次响应。

## 修改原因

V029至V038已覆盖类型详情和各垂直内容约束，但尚未在数据库层完整强制CONTENT_STATUS合法迁移、每次状态历史、提交版本快照、审核记录绑定版本、乐观版本单步递增和Outbox副作用；R12任务明确要求补齐迁移、唯一约束、状态历史、幂等边界与回滚验证。

## 影响摘要

在不新增业务表或第二状态机的前提下，将R12发布管理落实为数据库强制状态边、乐观版本、唯一迁移历史、可多事件审核快照绑定、事务Outbox、详情和媒体/联系方式唯一性及不可绕过的软删除，并补齐DELETE乐观锁合同与现有服务非法跳转。

## 迁移与兼容策略

V039先以父表优先的固定顺序锁定全部内容父子表，在任何DDL前审计非法状态边、活动详情缺失/错配、旧NULL/空联系方式、非法顺序、重复媒体/渠道/顺序、版本断层及无法绑定的非空审核记录；脏升级单事务原子失败。transition_version、snapshot_version_id、command_id允许旧行NULL且不伪造历史；V039后的新记录由触发器强制填充或显式提供并校验。父子删除统一先锁父行且无论DELETED与否均拒绝，content_media上的守卫同时阻断media_objects的ON DELETE CASCADE。DELETE操作当前只有冻结文档和生成类型，无后端DELETE控制器或生产消费者，因此在TASK-R12-003首次实现前补为必填expectedVersion，不需要并行v2。U039保留新增列和全部业务数据，只移除R12触发器/约束/索引并恢复被替换的旧对象定义；填充库可数据不变回滚并重放。R06-R11历史SQL测试固定在各自迁移边界；Flyway最新库的Store测试按R12创建/迁移证据更新。
