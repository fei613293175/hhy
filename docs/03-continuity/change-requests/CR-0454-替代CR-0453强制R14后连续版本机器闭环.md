# CR-0454 — 替代CR-0453强制R14后连续版本机器闭环

## 用户需求摘要

总结R14未完成却跳过R15进入R16的连续性错误根因，并强制更新既有规则与机器门禁；开发不得依赖聊天记录。

## 原规则

既有规则一方面要求逐版本核对，另一方面允许TEST_APK或候选失败后继续下一独立Release；continuity close仅按依赖图允许旁路，start/resume只信CURRENT_STATUS与NEXT_TASK，Android自动化规则也明确candidate失败不阻断下一版，形成可执行的规则冲突。

## 新规则

R14起下一业务Release只能是当前Release编号+1；项目所有者真机PENDING仍异步且不阻断，但上一Release必须全部TASK完成（close原子校验时仅把当前最终TASK按本次COMPLETED拟DONE）、同一冻结Commit的TEST_APK与测试文档/Manifest/Evidence身份一致、该Release与该Commit的GitHub真实交互候选PASS、machine completion PASS后才能跨Release领取。candidate FAIL或缺失、TASK未完、Manifest/Evidence/guide缺失、SHA/Commit/release错配、R14直跳R16均硬失败。start、无会话resume和close在任何状态写入前调用同一仓库证据校验；CURRENT_STATUS/NEXT_TASK不能单独证明完成。R13及以前owner异步尾部兼容仅保留历史。

## 修改原因

CR-0453已独立REJECTED并保留历史：遗漏Android自动化规则、测试体系、门禁脚本及其测试，且负向证据与close原子时序不足；本CR按审查意见完整替代。

## 影响摘要

完整原位修订连续性、Android自动化、测试体系与开发效率现有事实源；新增统一版本序列与机器闭环验证器，接入start/resume/close并保持close先校验后写入的原子性；登记本次漂移、踩坑与复用模式，纠正后续顺序为R14闭环、R15、R16。
