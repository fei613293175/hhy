# CR-0491 — 切换R14会话行操作为Compose语义并验证发送后输入清空

## 用户需求摘要

项目所有者要求由AI持续使用GitHub Actions自行审核R14，发现问题后不停止推进且不得弱化业务断言。

## 原规则

R14候选按UiAutomator导出的resource-id点击会话行、返回重进会话并长按删除；输入消息也通过UiAutomator直接设置Compose文本框。Attempt11首次运行因GitHub模拟器脚本启动前中断，按既有基础设施规则只重跑失败Job；重跑已完成真实旅程，但在拉黑成功、返回列表且GET会话列表200后，UiAutomator无法再次找到`r14.conversation.row`。

## 新规则

复用PROB-0125和PROB-0151，不新增并列全局规则：同一Compose候选旅程中的会话行点击、返回重进点击、长按与删除消失证明统一使用Compose精确`testTag`、唯一节点等待、`assertIsDisplayed`及原生语义动作；消息输入使用Compose `performTextReplacement`，发送成功后必须证明输入框为空再截图。仍保留服务端发送、未读、拉黑、重进、解除拉黑、长按删除、四张截图、JUnit和日志审核，不延长业务超时、不删除断言。

## 修改原因

Attempt11重跑Job 90712301167已证明POST拉黑200、随后GET会话列表200；数据库仍有当前会话且`hidden_at`为空，同时拉黑关系真实存在。失败仅为返回列表后`By.res("r14.conversation.row")`不可见，与既有“Compose testTag不保证稳定导出为UiAutomator resource-id”经验一致。前两张截图还显示UiAutomator直接设置的发送文本在成功后留在输入框，因此必须让输入和清空验证也回到Compose语义层。
