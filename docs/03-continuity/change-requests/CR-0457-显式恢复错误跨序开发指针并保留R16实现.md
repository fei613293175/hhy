# CR-0457 — 显式恢复错误跨序开发指针并保留R16实现

## 用户需求摘要

纠正R14未完成且R15未开发却进入R16的连续性错误；恢复R14继续开发，不依赖聊天记录且不得丢失已产生的R16代码。

## 原规则

新门禁能拒绝错误R16指针，但没有唯一的受审计退回命令；人工直接编辑CURRENT_STATUS/NEXT_TASK/Session/Task状态会破坏事件链，也可能丢失R16代码或把未完成任务伪标完成。

## 新规则

新增sequence-recover唯一命令：仅当当前R14+会话被前序机器闭环门禁拒绝时，自动定位最早未完成Release并且只允许退回其第一个未完成Task；执行前要求产品工作区干净、指定的R16 stash真实存在。命令原子保存恢复证据，终止错误会话和Claim，将错误跨序完成的R16 Task恢复为READY/BLOCKED待日后重验，保留所有Commit与stash；恢复R14 Task、CURRENT_STATUS、NEXT_TASK、事件链并立即创建R14 ACTIVE会话和检查点。失败必须零写入，不得人工伪改DONE。

## 修改原因

新门禁已正确拒绝resume，但当前仓库仍停留在历史错误R16 ACTIVE状态，需要一次受审计、可测试、保留实现的状态迁移回R14。

## 影响摘要

新增一次性且可复用的版本序列恢复命令与原子回归，用仓库证据把当前指针从R16恢复到R14，同时保留R16实现供完成R15后重新验证。
