# CR-0451 — 替代CR-0450修复R14消息体验并升级大版本交互候选

## 用户需求摘要

R14消息六项缺陷必须修复；每个Android大版本结束由AI在GitHub Actions模拟器实际点击、输入、长按并自主审核，不能只看截图；CR-0450因边界不完整已拒绝，现按独立审查意见重提。

## 原规则

CR-0412与CR-0414把GitHub模拟器候选降为按需非阻断专项，机器关闭可仅凭固定工具链TEST_APK推进；R14消息页各自维护顶栏、拉黑状态和删除入口，候选旅程仍硬编码R13。

## 新规则

R06至R32每个Android大版本最终machine completion前必须运行一次绑定该release冻结Commit的GitHub Actions交互候选：AI用UiAutomator/Compose真实点击、输入、长按、返回并断言业务状态、日志和截图；截图只能作为视觉证据，不能替代功能操作。普通提交、小版本和中间开发不得触发重型候选；TEST_APK可先交付；AI独立判定PASS/FAIL；owner真机反馈异步且不阻塞下一版本，只有production activation/close保留owner PASS。R14必须补做并通过后才恢复R16扩展。

## 修改原因

CR-0450已保留REJECTED审计历史；本CR精确修正接口、SharedPreferences隔离、staging夹具重建和完整交互断言范围。

## 影响摘要

原位反向修订CR-0412/CR-0414投影，不建立平行规则。修复readAt JSON缺失/null被误当有效字符串而假已读；消息主页和详情统一Material3 TopAppBar默认windowInsets及同一高度；删除动作从详情移除并迁至会话列表长按；关键词LIKE改用单字符!转义；本人拉黑成功后用SharedPreferences持久化并在重进/进程重建恢复解除拉黑与禁发状态。R14候选按release分派并准备隔离、可重复的聊天夹具，实际执行发送、搜索、拉黑、重进、解除和长按删除。
