# CR-0466 — 补齐R14至R32全链路版本连续性回归

## 用户需求摘要

项目所有者明确要求：防漂移不能只针对R14跳R16，必须保证后续持续开发至R32均不可发生版本或任务顺序漂移。

## 原规则

既有validate_sequential_release_number和validate_release_machine_chain已对R14以后版本通用，但tests/test_continuity_version_sequence.py只显式覆盖R14、R15、R16。

## 新规则

不新建平行硬规则；在原版本连续性测试事实源中显式覆盖R14至R32：逐个相邻版本转换均合法、任意非相邻前进均拒绝、R32准入必须逐版验证R14至R31机器闭环，且任一中间版本缺失或证据失败均阻断。

## 修改原因

既有核心实现按数值范围覆盖R14以后版本，但专项测试只显式证明到R16；需在原门禁测试事实源内补齐R14至R32的全链回归，避免未来修改造成未被发现的中后段漂移。

## 影响摘要

只增强既有连续性门禁的R14至R32回归证明，不改变产品、版本计划、完成状态或现有门禁语义。
