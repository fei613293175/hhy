# CR-0211 — 实现R08项目发布详情收藏分享会话及公共分享后端闭环

## 用户需求摘要

项目所有者要求持续推进R08，普通任务只运行受影响MODULE且不得等待真机反馈

## 原规则

contentPostContents与contentPatchContentsById把contacts定义为无渠道单字符串；contentPostContentsByIdFavorite未要求最后读取版本；contentPostContentsByIdShare响应仅允许ContentResource或CommandResultResource，无法返回动作名称承诺的分享地址；R08九端点中七个没有后端控制器或应用服务实现，相关业务配置也没有激活值。

## 新规则

发布和编辑使用结构化ContactInputResource数组明确channel与value并最多20项；收藏请求必须携带最后读取的expectedVersion并由服务端拒绝陈旧版本；分享返回专用ShareResultResource，包含contentId、channel、HTTPS url与acceptedAt；保留publicGetShareContentsById的R28归属但在R08实现项目分享兼容API。九端点复用R06列表与R07联系方式，其余七端点必须以真实PostgreSQL事务实现PROJECT范围，创建与编辑要求实名、编辑要求所有者和expectedVersion，收藏/分享/会话要求ONLINE项目，全部写操作使用稳定幂等、最小审计与Outbox。V034只种入配置注册表已冻结的12个内容/聊天默认值和domain.h5.host，不覆盖既有激活值。

## 修改原因

九端点审计确认列表与联系方式访问已由R06/R07实现，其余七端点缺失；冻结发布合同无法表达联系方式渠道，分享响应也没有URL，必须先做最小可用合同修正再实现真实事务、幂等、权限、审计和Outbox

## 影响摘要

修正三个不可用或不完整的冻结模型并完成R08项目发布、编辑、详情、收藏、分享、直接会话和公共分享七个缺失端点；补齐配置种子、运行时合同、生成客户端、权限幂等审计与PostgreSQL集成证据。
