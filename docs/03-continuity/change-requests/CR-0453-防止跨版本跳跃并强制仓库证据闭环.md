# CR-0453 — 防止跨版本跳跃并强制仓库证据闭环

## 用户需求摘要

总结R14未完成却跳过R15进入R16的连续性错误根因，并强制更新既有规则与机器门禁；开发不得依赖聊天记录。

## 原规则

既有AGENTS与效率规范要求版本核对，但又允许TEST_APK交付或大版本候选失败后继续下一独立Release；continuity跨Release仅校验依赖图，start只校验NEXT_TASK指针，不强制直接前序Release机器闭环，因此状态文件一旦漂移可跳过中间版本。

## 新规则

原位强化现有连续开发和版本关闭规则：R14起，项目所有者真机PENDING仍异步非阻断，但下一业务Release只能是当前Release编号+1，且必须在当前Release全部TASK为DONE、同Commit TEST_APK与测试文档成对交付、版本专属GitHub真实交互候选PASS、machine completion PASS后才能领取；候选FAIL、任一TASK BLOCKED/READY/IN_PROGRESS、缺APK/文档/Manifest/Evidence均阻断跨Release开发。continuity start/resume/close必须从仓库TASKS、Manifest、Candidate、Delivery和依赖图交叉验证，CURRENT_STATUS/NEXT_TASK不得单独作为完成证明；检测到R14未闭环或R15空缺却指向R16时硬失败并输出缺失项。R13及以前历史owner异步尾部仅保留兼容，不得扩展到R14以后。

## 修改原因

现有规则虽然要求版本核对，却同时允许TEST_APK或候选失败后继续独立下一版本，continuity start又只信NEXT_TASK/CURRENT_STATUS而不验证直接前序Release，导致R14未闭环、R15无实现证据时仍能进入R16。

## 影响摘要

消除规则自相矛盾和独立Release旁路；加入直接前序版本、连续编号、任务全DONE、R14+候选PASS、APK与测试文档交付、机器完成交叉门禁，并把同一校验接入start、resume/doctor和close。同步登记本次R14到R16跳跃问题与回归测试。
